# 测试指南

## 自动检查

运行 `python scripts/run_tests.py`。统一入口检查测试脚本登记状态，然后执行自动回归。CI 在 Ubuntu/Windows 与 Python 3.11/3.12 组合运行这条入口，并在 Windows 上单独构建未签名正式安装包、执行安装冒烟检查。开发环境细节见 [构建指南](BUILDING.md)。

Ubuntu 上的面板源码检查显式加载 `.pyw` 文件，托盘菜单模型使用无界面后端；原生 Windows 窗口检查仍在 Windows 上进行。

当前入口在项目目录运行测试，部分测试可能读取本机运行数据；发布前应在不含个人配置和 `data/` 的独立源码副本中验证，并避免不同测试共享运行数据。X 转发组测试使用固定 RSS 样例和模拟投递，不要求本机 RSSHub。

Steam 的针对性检查为 `python -m unittest scripts.test_steam`，覆盖来源解析、逐群基线、公告去重与接口故障补查、游戏/DLC/捆绑包折扣和发行状态变化、队列持久化及群发送失败隔离，并使用模拟 QQ 连接检查官方及个人 QQ 发送；不连接真实 QQ，不读取本机凭据。安装 Node.js 时还运行隔离 DOM 中的 Steam 页面保存与草稿检查；没有 Node.js 时该项跳过。

## 手工检查

桌面界面、托盘、安装/卸载和真实平台投递需要手工验证。使用获授权的测试账号、频道和群；不要在生产群里发送测试消息。记录版本/提交、复现步骤和预期结果。在非输入区域输入 wrelayreminder 可预览维护提醒，输入 wrelayfail 可切换失败光效预览；输入 wrelayclear 清除这两种测试预览并恢复真实状态。清理口令不会改变机器人或连接状态。

## 数据保护

不得将 .env.prod、data/、数据库、完整日志、真实平台标识符或消息内容提交到测试报告。确需提交日志时，先删去凭据、OpenID、频道/群组 ID 和消息正文。
