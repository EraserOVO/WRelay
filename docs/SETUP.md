# WRelay 安装指南（Windows）

WRelay 包含五条独立链路：Discord → QQ、X/Twitter RSS → QQ、Bilibili RSS → QQ、YouTube RSS → QQ，以及授权用户通过
QQ 私聊命令执行的 QQ → QQ 手动转发。不提供 QQ → Discord 自动转发，也不做双向同步。

---

## 1. 前置条件

- Windows 10 / 11
- 正式安装包无需预装 Python；仅源码安装需要 64 位 Python 3.10 或更高版本（安装时勾选 **Add to PATH**）
- QQ 官方机器人账号；选择 Discord 用途时还需 Discord Bot 与可访问 Discord 的网络（见第 7 节）
- 选择 X/Bilibili 用途时需可访问的 RSSHub 服务；YouTube 使用官方频道 RSS，不需要 RSSHub；这三种用途都无需配置 Discord

---

## 2. 一键安装

1. 普通用户运行 `WRelay-Setup.exe`，安装后从桌面或开始菜单打开 WRelay。源码用户把整个项目放到一个目录（例如 `C:\WRelay`）。
2. 正式安装包会在当前用户的 Windows“已安装的应用”中注册 WRelay，建立开始菜单、桌面和卸载入口，并从 `.env.example` 生成 `.env.prod`。源码用户**双击 `install.bat`**，脚本会自动：
   - 源码版本若没有内置 Python，则创建虚拟环境 `.venv`
   - 源码版本按 `requirements-lock.txt` 安装已验证的固定版本依赖
   - 以可编辑模式安装项目（`pip install -r requirements-lock.txt -e .`）
   - 源码版本若不存在 `.env.prod`，从 `.env.example` 复制生成
3. 源码用户**双击 `启动面板.bat`** 打开 WRelay 桌面窗口。
4. 未配置的新安装会自动显示配置向导；已有用户从「设置 → 应用 → 配置向导」进入。基础账号、来源与接收群均可通过界面完成，无需手动编辑 `.env.prod`。
5. 按向导选择用途并完成下方流程。账号保存后，由用户主动启动／重启检查；最后确认启用转发规则。

### 首次配置向导

1. **用途**：选择 Discord 频道、X 动态、Bilibili 投稿或 QQ 授权私聊转发。一次配置一种，完成后可以继续添加。
2. **账号**：所有用途都需要 QQ AppID/AppSecret；Discord 分支额外要求 Token。已有账号可以复用，留空密钥保留原值。先保存，再点击「启动／重启并检查」，几秒后刷新连接状态。重启作用于整个机器人进程。
3. **授权用户**：新增接收群时，让可信用户私聊机器人点击“提交用户注册”按钮（或发送 `/注册`），即可按当前用户身份提交申请，无需填写 QQ 号或昵称。申请人会收到 `XXXX-XXXX` 识别码，可转交管理员以对应审核列表中的 OpenID；识别码不代表授权。已登记（`qq_user_openids` 中已有该 OpenID，不论是否勾选）的用户再次提交会提示无需重复申请，待审核用户再次提交会返回原识别码。向导刷新并审核后还需单独点击授权。授权同时开放现有私聊管理命令（包括 `/重启`），不能把它理解为仅能提交群申请。已有群的自动转发可以跳过此步；QQ 私聊分支必须选择已授权用户。
4. **接收群**：由已授权用户在群内发送 `/注册群`，即可按当前群身份提交申请，无需填写群号或群名。申请人会收到申请识别码，管理员可在注册审核列表粘贴识别码定位待审记录，然后刷新、审核并勾选。已登记群不能重复申请，待审核申请重复提交时会返回原识别码。只显示当前 Bot 的群；单 Bot 的旧版未绑定群也可复用，多 Bot 的未绑定群需先确认归属。群审核后仍未启用，最后确认才启用。
5. **内容来源**：Discord 扫描并选择可读频道；X 填用户名；Bilibili 选择 UP 主 UID、标签或关键词。也可以复用已有来源。RSS 检测会读取真实来源，但不会投递消息或安装 RSSHub。
6. **确认启用**：显示账号、来源和目标群，确认后保存。来源／群的全局启用也会影响其他包含它们的转发组；RSSHub 地址由同一链路的来源共用，确认页会提示。已有来源筛选条件保持生效。
7. **验证结果**：Discord 主动发送新消息；RSS 等待新内容（首次只建立基线）；QQ 用户私聊用 QQ 的“回复”引用一条测试消息后发送 `/转发 序号`（如 `/转发 1`）。结果页只把匹配本次来源、所选全部群、保存后产生的成功记录视为投递证据。“我已在目标群收到消息”单独记录为用户确认。

点击「稍后配置」或关闭向导会保存当前非密钥输入，下一次从设置进入可继续；每次进入下一步也会保存进度。突然终止程序时，当前步骤尚未保存的输入可能丢失。AppSecret/Token 不写入进度文件或浏览器存储，未提交的密钥关闭后需重新输入。

进度保存在 `data/onboarding.json`，真实转发配置仍保存在 `data/settings.json`。向导进度不纳入配置备份，恢复配置后可以从设置重新进入。已有账号或来源的用户不会被自动弹窗打断。
如果进度文件损坏或无法读取，向导会报告错误并保留文件；修复或移走该文件后，缺失文件会按首次空进度重新开始。

QQ 分支只引导授权私聊手动转发。该授权用户仍可选择所有全局已启用的接收群，本次勾选不是单用户访问范围；向导不创建 QQ 群聊互转组，也不改变现有群聊路径的权限实现。

安装器创建的桌面和开始菜单快捷方式、任务管理器中的可执行程序、桌面窗口及托盘图标使用 WRelay 主标识。机器人进程显示为 WRelay.Bot；Windows“已安装的应用”提供卸载入口。安装器会在缺少 WebView2 Runtime 时安装微软官方组件，因此首次安装可能需要联网。
桌面程序首次打开进入运行总览，显示机器人及各转发链路状态、配置数量和最近消息；Discord → QQ、X → QQ、YouTube → QQ、Bilibili → QQ、QQ → QQ 链路分别进入对应管理页。设置页提供日间/夜间主题、正常状态卡渐变扫光动画开关、应用版本和 GitHub 最新稳定版更新检查；“应用”卡片中的“自动检查更新”默认开启（启动后自动检查一次），发现新版本后“检查更新”按钮变为“立即更新”，点击后下载官方安装包并显示进度百分比与当前步骤，然后启动安装向导由用户确认安装，不会静默替换正在运行的程序。机器人账号、翻译服务、启动方式、备份与诊断也可从设置页进入。全局运行日志位于「设置 → 启动与维护 → 运行日志」，点击「查看」打开窗口，保留级别筛选、消息追踪、自动滚动、复制及确认清空；五个链路页面不再重复显示日志卡片。
不同来源页面的转发组与白名单表格保持原有操作。QQ 用户白名单不在设置页：在「QQ → QQ」页的「转发组」区域中，左栏「QQ 转发群」、右栏「QQ 授权用户」，两侧各带自己的「＋ 新增 / 注册审核」按钮，勾选即保存生效。关闭窗口默认隐藏到托盘。设置 → 外观与窗口 → 关闭窗口行为可改为“退出桌面端”或“每次询问”，保存到 `data/desktop_preferences.json` 并立即生效；选择“退出桌面端”时窗口直接关闭，三种关闭方式都不会停止机器人。原生托盘菜单提供打开、总览、设置与进程快捷操作；“退出桌面端”保留机器人但停止看护，“停止机器人并退出…”会先确认，停止失败则保留桌面端。
配置表会按可用宽度调整列，长 ID 显示省略号、悬停可查看完整值并可复制。窄窗口会将侧栏收起为图标导航、将转发列表调整为单栏，并在更窄时隐藏次要的 QQ 账号列。
管理页面仅在桌面窗口中打开，桌面程序不再监听 `18090` 或提供浏览器备用入口；机器人自身的 `18082` 本机接口继续运行。桌面布局参考见 [设计概念图](DESIGN.md)。

如果还要转发 X/Twitter 或 Bilibili，请先准备可访问的 RSSHub，在桌面端对应链路页面登记来源、
加入转发组并启用目标 QQ 群。YouTube 可直接在「YouTube」页登记频道 ID、`@handle` 或频道主页链接，
使用官方 RSS，不需要 RSSHub。配置完成后启动机器人。

> 正式安装后从开始菜单或桌面打开 WRelay；源码运行才使用 `启动面板.bat`。WRelay 管理程序运行期间会看护机器人；机器人开机自启时从托盘后台启动管理程序并自动拉起机器人。

启用开机自启后，Windows 任务管理器的启动应用列表会显示名称 **WRelay**，并从正式版 `WRelay.exe` 读取应用图标。升级会把旧版启动文件迁移到当前用户的 Windows 启动注册项；关闭开关或卸载时会清理对应注册项。

## 3. 开发者构建安装包

正式安装包使用 Nuitka 编译自有 Python 代码，再由 Inno Setup 制作 `dist/WRelay-Setup.exe`。源码开发、CI 检查和 Windows 安装包构建方式见[开发与构建指南](BUILDING.md)；不同版本不能同时占用机器人服务端口。

安全依赖使用 `cryptography==50.0.1` 与 QQ 适配器 `1.7.2+wrelay.1` 本地元数据补丁，
完整来源、摘要与复现方法见 [vendor/README.md](../vendor/README.md)。源码安装需保留 `vendor/wheels/`，
并始终配合 `requirements-lock.txt` 安装；仅执行 `pip install -e .` 无法从 PyPI 找到本地补丁版本。
multidict 固定为 `6.9.1`，修复 `6.7.0` 至 `6.9.0` 的 items-view 并集／差集引用泄漏（[GHSA-54p9-h82j-f925](https://github.com/aio-libs/multidict/security/advisories/GHSA-54p9-h82j-f925)）。构建前的安全依赖检查也要求此版本；转发逻辑不变。
补丁不改变 QQ 适配器的运行代码。升级依赖后必须重新运行下方准备脚本；构建脚本会拒绝旧依赖，
避免把仍含漏洞的 `.runtime/python` 打进新安装包。

源码用户应先停止机器人与桌面端，再使用 `.venv/Scripts/python.exe -m pip install -r requirements-lock.txt -e .`
更新运行环境，执行 `.venv/Scripts/python.exe -m pip check` 后重新启动。
安装包用户需重新构建并安装新包；Git 提交或推送本身不会更新已经安装的程序。
安装包把 `panel/web/` 前端资源复制到安装目录，桌面窗口直接从该目录加载 `index.html`；修改工作区文件不会热更新已安装副本。更新界面需安装包含新资源的版本，若直接更新已安装资源则需重启桌面端让 WebView 重新加载。

离线兼容验证：`python scripts/test_qq_crypto_compat.py`。该测试已加入统一回归入口，
检查握手签名、回调验签及拒绝伪造请求，不连接真实 QQ 或 Discord。

需要联网下载构建依赖，并先安装 Inno Setup。首次准备构建环境时，在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare_runtime.ps1
```

准备脚本会下载固定版本的 `python-build-standalone` Windows x64 运行时，校验 SHA-256，并准备 WebView2 安装器。然后创建专用编译环境并安装锁定依赖及 Nuitka：

```powershell
.\.runtime\python\python.exe -m venv .runtime\compile-env
.\.runtime\compile-env\Scripts\python.exe -m pip install -r requirements-lock.txt -r requirements-build.txt
```

准备完成后，在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_installer.ps1
```

脚本检查锁定依赖与 WebView2 安装器签名，编译 `WRelay.exe`、`WRelay.Bot.exe` 和 `WRelay.Restart.exe`，审计安装目录后编译 `WRelay.iss`。正式版只允许从干净、已提交的 Git 工作树构建。构建器用 Authenticode/SHA-256 和 RFC 3161 时间戳签署 WRelay 程序与标题栏组件；Inno Setup 再签署安装程序和卸载程序。签名验证通过后才生成 `dist/WRelay-Setup.exe` 和同目录的 SHA256 文件。缺少证书或签名工具时，正式版构建会停止。若编译器不在常见安装目录，可以先设置 `INNO_SETUP_ISCC` 为 `ISCC.exe` 的完整路径。安装包不分发项目自有 Python 源码或字节码；Web 前端资源仍随包提供。

公开发行需要受信任证书颁发机构签发、带 Code Signing 用途及私钥的 Authenticode 证书。将证书安全导入 Windows 当前用户或本机个人证书库，并设置：

```powershell
$env:WRELAY_SIGN_CERT_SHA1 = '<40 位证书 SHA1 指纹>'
$env:WRELAY_TIMESTAMP_URL = '<证书提供方的 HTTPS RFC 3161 时间戳地址>'
# 可选：若 signtool.exe 不在 PATH 或 Windows SDK 默认目录
$env:WRELAY_SIGNTOOL = '<Windows SDK 中 signtool.exe 的完整路径>'
```

不要提交私钥/PFX 或密码，也不要通过聊天发送。自签名证书不能替代公开发行所需的受信任发布者证书。

`pyproject.toml` 也提供标准 Python 构建元数据，可用于构建插件依赖包；它不是完整的桌面应用安装方式。
完整的 Bot、桌面窗口及 Windows 快捷方式请使用上面的 Inno Setup 安装包。

发布前请记录构建脚本输出的 SHA256，并在分发端验证：

```powershell
Get-FileHash .\dist\WRelay-Setup.exe -Algorithm SHA256
```

构建完成后，可在尚未安装正式版的机器上执行隔离安装验证：

```powershell
.\.runtime\compile-env\Scripts\python.exe scripts\test_compiled_installer.py dist\WRelay-Setup.exe --edition release --skip-desktop
```

脚本在独立临时目录安装并检查 Windows 卸载注册、开始菜单快捷方式、编译程序、依赖及未配置时的安全退出，再卸载并确认保留用户数据；`--skip-desktop` 避免与正在运行的机器人争用端口。已有正式版安装或正式版开机启动项时脚本会拒绝运行，避免临时安装更改现有设置。

GitHub Actions 会准备锁定依赖与编译环境，构建未签名的隔离测试版，再安装到独立目录执行编译版冒烟检查；CI 不生成可公开发行的正式安装包。
推送和 Pull Request 都会触发该检查。

发布包中不得包含 `.env.prod`、`data/` 运行数据或其他真实凭据。正式版应同时验证 Authenticode 签名并提供 SHA256；校验值应通过可信渠道分发。

## 4. `.env.prod` 配置详解

| 配置项 | 含义 | 说明 |
|---|---|---|
| `DISCORD_BOTS` | Discord Bot 的 token | Discord 用途需要，见第 5 节；其他用途可留模板占位或使用空列表 |
| `DISCORD_PROXY` | Discord／X／YouTube 媒体 HTTP 代理 | 可选；例如 `http://127.0.0.1:7897`，端口需与本机代理软件的 HTTP／混合端口一致；用于 Discord API、Gateway、Discord 托管媒体、X/Twitter 媒体 CDN（`pbs.twimg.com`、`video.twimg.com`），以及 YouTube 频道 RSS 与封面下载 |
| `QQ_BOTS` | QQ 官方机器人的 AppID / AppSecret | 见第 6 节；`id` 与 `token` 都填 AppID，可在向导填写 |
| `HTTP_PROXY` | 通用代理环境变量 | Bot 启动时会清除；Discord API/Gateway、X/Twitter 媒体与 YouTube RSS/封面请使用 `DISCORD_PROXY`，其他出站流量使用系统／TUN 路由 |
| `LOG_LEVEL` | 日志级别 | 默认 `INFO`；排查问题时可改 `DEBUG` |
| `HOST` / `PORT` | Bot 本地 HTTP 服务地址 | 保持 `127.0.0.1` / `18082`；管理面板借此读取状态、消息追踪和执行补发，不要改为局域网地址 |
| `API_TIMEOUT` | 媒体下载超时（秒） | 默认 120 |
| `MEDIA_CONCURRENCY` | 同时下载的媒体数 | 默认 4 |
| `MEDIA_MAX_BYTES` | 单文件大小上限（字节） | 默认 30MB，超限降级为链接 |

这三项必须是正数；空值、无效值或非正值会回退到表中默认值。

`QQ_BOTS` 的 `intent` 决定机器人订阅哪些事件。QQ 消息按钮（`/菜单`、`/定时消息` 等回复中的按钮）使用「指令按钮 + 自动发送」，点击后由客户端把中文斜杠命令作为普通消息发出，因此不需要额外的 `interaction` 事件；但需要 QQ 客户端版本 8983+，旧版本点击按钮只会把命令填入输入框。若把 `QQ_BUTTON_MODE` 改为 `callback`，按钮变成回调按钮，需要同时订阅 `interaction` 事件（`QQ_BOTS` 的 `intent.interaction = true`）并且开放平台接入方式为 Webhook——WebSocket 接入下点击会提示「请求第三方失败」，因此默认仍为 `enter`。

私聊 `/菜单` 提供运行总览、手动转发、定时消息、注册申请和重启五个手机常用入口。「手动转发」发送 `/转发 列表`，返回纯文本目标名单和用法，不再需要逐群勾选。注册申请入口可查看用户/群待审核申请并提交用户申请；自动转发组、Bot账号、QQ群、权限用户和离线补发等低频查看/维护入口不列入主菜单。群聊不再提供独立菜单；群聊发送 `/菜单` 或单独 @机器人（不附带文字、附件或引用）会显示当前群可转发目标列表，@机器人后带内容、普通聊天和未知斜杠命令都不回复。群注册仍可由已授权用户发送 `/注册群` 申请。

> `.env.prod` 包含密钥，**绝对不要提交到 git 或外传**。

## 5. 创建 Discord Bot

1. 打开 [Discord Developer Portal](https://discord.com/developers/applications)，点 **New Application**。
2. 左侧 **Bot** 页 → **Reset Token** → 复制 token，填到向导的 Discord Token 输入框，或「设置 → Discord Bot」。
3. 在同一页面打开 **Message Content Intent**（特权网关意图，否则收不到消息正文）。
4. 邀请机器人进服务器：**OAuth2 → URL Generator**，勾选 `bot` 权限，再勾选需要的权限（`Send Messages`、`Read Messages/View Channels`、`Read Message History` 等），用生成的链接邀请。
5. 连接成功后，在向导点击「扫描可读取频道」并选择。手动管理也可在 Discord 页面使用「从全部可读频道注册」，然后加入转发组并启用。

## 6. 创建 QQ 官方机器人

1. 登录 [QQ 开放平台](https://q.qq.com)，创建应用/机器人，获得 **AppID** 和 **AppSecret**。
2. 在向导或「设置 → QQ Bot」中填写 AppID/AppSecret，保存后启动／重启检查连接。
3. 先由可信用户私聊点击“提交用户注册”按钮或发送 `/注册`，让申请人把机器人返回的 `XXXX-XXXX` 识别码交给管理员核对，在面板审核并明确启用该用户。
4. 把机器人拉进目标 QQ 群，由已授权用户发送 `/注册群`；同样可用返回的识别码对应审核记录。
5. 在向导或「QQ 接收群 → 注册审核」中审核申请。审核后仍需勾选启用、加入对应转发组；向导会在最终确认时完成所选群的启用与路由保存。自动发现 OpenID 只记录身份，不等于授权。

多个 QQ Bot 时，打开管理面板的「QQ Bot 配置」，点「添加 QQ Bot」并填写新的
AppID / AppSecret。面板左上角的 QQ Bot 下拉框用于切换工作区；Discord → QQ
与 X → QQ 页面只显示该 Bot 发现的目标群，新发现或注册审核通过的群会自动归属
发现它的 Bot。这样不必逐群选择 Bot；同一个实体群可由多个 Bot 分别发现并配置为目标。
旧配置中没有 Bot 归属的群继续按第一个 Bot 处理。选择框会显示当前 Bot 的连接状态；
单 Bot 且机器人进程尚未重启、暂时无法提供逐 Bot 状态时，会沿用整体 QQ 状态显示；
多 Bot 暂时无法提供逐 Bot 状态时才会显示「状态未知」，不会把其他 Bot 的连接状态误算过来。
保存凭据后面板会自动重启机器人。

> 说明：
> - QQ 官方机器人使用 **group_openid**（不是群号）；同一个实体群对不同 Bot 会分别记录各自的 OpenID，无法推算，只能让每个 Bot 入群后自动发现。
> - 公域机器人需要群主开启「主动消息」权限，且可能有时段/频率限制；想稳定使用建议申请转私域。
> - 机器人无法给未配置 openid 的群发消息。

### X/Twitter RSS 转发

1. 准备一个可从本机访问的 RSSHub 实例（默认配置通常为 `http://127.0.0.1:1200`）。
2. 在管理面板 X 来源行登记账号或 RSSHub 来源；来源漏斗可并列设置关键词/话题、推文类型（原创/转发/引用）和消息类型（文字/图片/视频）。
3. 创建/选择 X 转发组，把 X 来源和已启用的 QQ 群加入同一组并保存。
4. 点击 X RSS 状态卡右侧的限速表图标，可调整最短发送间隔、每小时上限、每来源积压上限和积压超限策略。默认值为 5 秒、每小时 300 条、每来源 100 条；限速按全部 X 来源合计。
5. 启动机器人后，面板会显示轮询状态、最近结果、当前积压和失败原因。

来源筛选按各自可发送的消息组件类型控制渲染；视频媒体被筛掉时不发送媒体，也不发送下载失败后的媒体链接。消息类型与现有推文/投稿类型、关键词是独立条件；若同时配置，条目必须通过内容类型及消息组件筛选（交集）才能进入 QQ 投递。未配置新消息类型字段的旧来源默认全开，X/Bilibili 旧配置值“文件”读取时迁移成“视频”，不改变 Discord 附件筛选。

RSSHub 请求失败、QQ 暂时未连接或发送失败时不会推进来源游标，恢复后会继续
尝试。对临时的 HTTP 429、5xx 和连接异常，WRelay 会在同一轮内退避重试最多 3 次；
其他 4xx 会立即报告。RSS 使用 ETag/304 缓存减少重复请求；RSSHub 必须能被运行
WRelay 的机器访问。若 RSSHub 暂时不可用，WRelay 会回退到 X 公开时间线继续轮询；
若回退接口也被限流或持续失败，再检查网络、RSSHub 服务和地址。

若 RSSHub 与本程序由同一次开机启动拉起（例如 RSSHub 运行在 Docker Desktop 中），
WRelay 启动后 4 分钟内的连接被拒会被视为“等待 RSSHub 启动”：状态卡显示
“等待 RSSHub 启动”，不记为请求失败，也不累计到维护告警的连续失败次数。
宽限期结束后仍不可达才会报告 RSSHub 请求失败。
推文进入持久化队列后由单独的后台任务依次投递；QQ 暂时离线或发送失败时会保留未完成条目，机器人恢复后继续处理。队列保存在 `data/x_protection.json`，包含运行状态的配置备份会一并保存该文件。

### Bilibili RSS 转发

1. 准备一个可从本机访问的 RSSHub 实例，默认地址为 `http://127.0.0.1:1200`；在面板 Bilibili 页修改 RSSHub 地址和轮询间隔。
2. 点击「注册来源」，选择范围并填写：UP 主使用数字 UID，标签或关键词使用对应文本。注册与来源选择器直接显示 UID、标签名或关键词，不提供自定义显示名称。
3. 点击已注册来源行尾漏斗进入「消息筛选」：添加关键词并选择关键词筛选、消息类型（文字、图片、链接、视频）及投稿类型（UP 主来源可选视频、专栏、动态；标签与关键词来源只支持视频）。各筛选维度同时设置时取交集；关键词按标题、简介、作者和分类标签匹配，不区分大小写；不再提供额外标签、标题包含/排除或作者白名单条件。
4. 创建/选择 Bilibili 转发组，把 Bilibili 来源和已启用的 QQ 群加入同一组并保存。
5. 点击 Bilibili RSS 状态卡片右下角的限速表图标，调整保护参数：最短发送间隔、每小时最多发送条数、每个来源积压上限，以及超限时“保留最新、跳过旧投稿”或“保留最旧、跳过新投稿”。
6. 消息类型勾选「视频」时即对视频投稿尝试上传视频本体；超过媒体大小上限（默认 30 MiB）、视频分段或下载失败时发送视频链接，取消「视频」则连视频链接也不发送。
7. 启动机器人后，Bilibili 页会显示来源数量、最近轮询、发现、发送和当前积压统计。首次启用来源或 QQ 群时建立游标基线；UP 主专栏/动态 feed 首次启用时也分别建立基线，不补发已有历史。

UP 主视频、专栏和动态分别使用 RSSHub 的 `/bilibili/user/video/{uid}`、
`/bilibili/user/article/{uid}` 和 `/bilibili/user/dynamic/{uid}` 路由；标签和关键词仅使用
`/bilibili/vsearch/{关键词}/pubdate/0` 视频路由。转发消息使用“自动转发来自 Bilibili 中[UP 主名称]的投稿”来源头，优先显示 RSS 投稿作者，缺少作者时回退到注册来源值；
并只包含标题、纯文本原始投稿地址
和封面图片，不发送作者、标签、其他分类、简介及播放统计。来源漏斗的消息类型勾选「视频」时即尝试上传单段视频；视频超过媒体大小上限（默认 30 MiB）、分段或下载失败时发送链接，不勾选「视频」则连视频链接也不发送。RSSHub 请求失败、QQ 暂时未连接或发送
失败时不会推进来源游标，恢复后继续尝试。与 X 链路相同，启动后 4 分钟内的 RSSHub
连接被拒视为“等待 RSSHub 启动”，不计入失败轮次。

保护参数是应用层的保守上限，不等同于 QQ 官方平台公布的配额。推荐先使用默认值：每条之间至少
间隔 60 秒、每小时最多 10 条、每个来源最多积压 10 条；热门标签建议选择“保留最新、跳过旧投稿”，
避免热门内容形成长期欠账。限速队列会保存到 `data/bilibili_protection.json`，机器人重启后继续按
当前配置发送，不会把积压一次性冲出。
若队列文件整体无法读取或格式无效，Bilibili 自动投递会暂停、不推进游标，并在状态卡与运行日志显示原因；
状态卡会显示“投递保护异常”，区别于 RSSHub 请求失败。修复文件或从备份恢复后会自动重新加载。
若损坏内容无法恢复，应先保留损坏文件副本，再重建空队列，并保留 `bilibili.json` 的来源游标和投递去重记录；
已经丢失且不再出现在 RSS 中的积压投稿无法找回。
来源基线和 feed 缓存另存在 `data/bilibili.json`；若文件无法读取或结构无效，来源轮询会暂停，避免重建专栏/动态基线时跳过投稿。基线写入失败时当前来源本轮中止，并在后续轮询重试。修复文件或从备份恢复后会自动继续。

若使用 Docker 运行 RSSHub，Bilibili 标签/关键词路由以及部分 UP 主动态路由可能需要 Playwright Chromium 运行时。建议使用
`diygod/rsshub:chromium-bundled` 镜像；若日志出现
`Executable doesn't exist at /root/.cache/ms-playwright/...`，还应持久化
`/root/.cache/ms-playwright` 并补齐 Chromium 的系统库。如果 Bilibili 上游返回
`412 Precondition Failed`，RSSHub 通常会对外显示 503；也可以为 RSSHub 配置有效的
`BILIBILI_COOKIE_1`，但 Cookie 只能放在本机环境变量或未提交的 Compose 配置中，不要写入仓库。

1. 在面板「YouTube」页点击「注册频道」，填写 `UC` 开头的频道 ID、`@handle`，或直接粘贴频道主页地址。
   来源使用 YouTube 官方 `feeds/videos.xml`，不需要 RSSHub 或 API Key；`@handle` 首次轮询时解析为频道 ID，
   解析结果缓存到 `data/youtube.json`。
2. 创建/选择 YouTube 转发组，把已启用频道和已启用的 QQ 群加入同一组并保存。首次启用来源或新增目标群时
   建立游标基线，不补发频道已有历史。
3. 点击来源行尾漏斗可设置关键词（在标题、简介和频道名中不区分大小写匹配）和消息类型（文字、图片、链接）；
   多个条件同时设置时取交集。关闭“文字”不发送标题，关闭“链接”不发送视频地址，关闭“图片”不下载封面。
4. 每条新视频发送来源头、标题、封面和视频链接，**不解析、不下载也不上传视频本体**。第一期不支持关键词/
   搜索类来源，也不提供 YouTube 手动转发。
5. 点击 YouTube 状态卡右下角的限速表图标，可调整最短发送间隔、每小时最多发送条数、每个来源积压上限和
   超限策略。默认 60 秒、每小时 10 条、每来源积压 10 条；积压队列保存在 `data/youtube_protection.json`，
   重启后继续按当前配置发送。
6. 轮询间隔默认 300 秒，低于 30 秒按 300 秒处理。QQ 未连接时不请求 YouTube；恢复连接后继续轮询。
   频道解析与 ETag 缓存保存在 `data/youtube.json`，投递游标写入 `data/discord_last.json` 的
   `youtube:<来源 ID>`。
7. 若本机访问 YouTube 需要代理，沿用 `.env.prod` 的 `DISCORD_PROXY`；该代理同时用于频道 RSS 和封面下载。
   封面下载失败时降级为图片链接。翻译由共享「自动翻译」卡片的 YouTube 链路开关批量控制，每个来源仍可
   单独调整翻译方式；翻译时跳过来源头，只处理标题和链接。

### Bilibili 自动解析

1. 在面板「Bilibili」页转发组卡片下方的「自动解析」卡片打开开关（默认关闭）。功能只对
   `qq_group_openids` 中**已登记且启用**、且属于当前 Bot 的 QQ 群生效，不提供额外的群选择器。
2. **前提**：群管理员需在 QQ 机器人资料页开启「接收所有消息」，否则官方网关不会把群内普通消息
   推送给机器人，机器人收不到任何链接。程序不会、也无法代为开启该开关。
3. 群成员发送 Bilibili 投稿视频链接（`bilibili.com/video/BV…`、`av…`，支持 `?p=` 分 P）或
   B 站 App 分享出的 `b23.tv` / `bili2233.cn` 短链时，机器人取该条消息中的**第一个** Bilibili
   链接，短链先跟随重定向再判定类型，然后下载视频本体并以被动回复把视频文件发回同一个群。
   只发视频文件，不额外发送标题消息。
4. 下载失败、超过媒体大小上限（默认 30 MiB）或视频不是单段时静默跳过，不回复提示或
   原视频链接；直播、番剧、专栏、动态与其他站点的链接同样不响应，也不会报错。
5. 同一个群内同一视频（按投稿编号与分 P）10 分钟内只发送一次，并有在途去重避免并发重复下载；
   该窗口只在进程内存中，机器人重启后重新计数。
6. 机器人自己发送的消息、以 `/` 开头的命令、@ 机器人的消息和私聊消息都不会触发；群聊的 @
   提示只回应单独 @机器人，@机器人时将链接一并发出不会被解析。
7. 视频抓取复用 Bilibili 公开接口，不携带 Cookie：仅 UP 主可见、审核中等需要登录态的投稿
   同样静默跳过。不引入 ffmpeg、yt-dlp，也不处理高清 DASH 或多段合并。
8. QQ 小程序分享卡片依赖适配器保留官方事件里的 `ark_data`，当前本地适配器未保留，
   该形式**暂不支持**；这类消息按普通文本处理（无链接即静默）。

### 桌面端诊断与投递追踪

- 设置页中的「连接诊断」只读显示机器人进程、Discord、QQ 连接和待重试投递数量，
  可手动刷新，不会发送测试消息。
- QQ 或 Discord 连续不可用 2 分钟时，面板看门狗会重启机器人进程尝试恢复连接；这会让另一平台同时短暂重连。
  同一连接持续故障时，自动恢复重启的间隔会从 5 分钟逐步延长，最长每小时一次；双链路同时故障时共享重启冷却。
- 总览「最近消息」卡片的「更多」和「设置 → 启动与维护 → 运行日志」窗口中的「消息追踪」会打开二级窗口，可查看最近 50 条投递结果、目标群、
  失败原因和重试次数。
- 「失败通知」和「随 Windows 启动」统一位于「设置 → 启动与维护」。启用后，仅白名单中已启用且勾选「告警」的用户会
  按冷却时间收到投递失败通知；重复失败会合并，不会连续刷屏。

### QQ 私聊手动转发

白名单用户私聊机器人发送 `/转发 列表`（也可用 `/私聊转发`）查看全部已启用接收群的纯文本编号名单和转发方法；名单不再附带按钮。用 QQ 的“回复”引用要转发的消息后发送 `/转发 1 3`，即可把这条消息发往对应序号的群；未引用时使用该用户最近一条普通消息（600 秒内），也可以先发内容再发命令。普通文字消息在缓存为最近内容的同时仍会收到「未知命令」提示，不影响之后引用或回退转发；直接发送 Discord / X / Bilibili 链接时只缓存为待转发内容，不再回复「未知命令」。`/转发 全部` 可一次发往全部群。序号越界会提示找不到转发群，重复序号自动去重。

群聊使用同一套「引用 + 序号」交互：`/转发 列表` 只列出与当前群同属一个 QQ 转发组的其他群，`/转发 1 3` 同样优先使用引用，未引用时使用该成员最近一条群消息；群聊不提供 `/转发 全部`。机器人消息、以 `/` 开头的命令消息和空引用不会被转发。
引用或最近内容也可以是 Discord 消息链接、X/Twitter 状态链接或 Bilibili 链接（投稿视频、专栏、动态，包括 b23.tv 短链接）。Bilibili 视频手动转发会尝试发送封面和视频本体；超出媒体大小上限、多段视频或下载失败时发送链接。专栏与动态使用 opus 链接（`bilibili.com/opus/{id}`，历史 `/dynamic/{id}` 同样支持），专栏发送标题、简介摘要、封面和专栏地址，动态发送正文、封面和动态地址；两者都不会尝试上传视频本体。该内容通过 Bilibili 详情接口按链接直接抓取，不携带登录 Cookie，因此仅 UP 主自己可见等需要登录态的内容仍无法获取。三条链路的手动转发统一在「QQ → QQ」页的紧凑「手动转发」卡管理：左下角「已注册来源」按钮打开弹窗，用 Discord / X / Bilibili 三个 Tab 分别查看已注册频道/账号/来源；右下角「消息筛选」用同样三个 Tab 分别编辑各链路的消息类型筛选，视频本体按“视频”类别控制（旧配置里的“文件”会自动迁移为“视频”）；筛选作用于对应链路的所有手动转发链接，窗口内只显示该链路可用的筛选项。它与其他 QQ 私聊手动转发共用同一套已授权 QQ 用户白名单，该名单在「QQ → QQ」页转发组的「QQ 授权用户」栏勾选维护。
该功能是授权的 QQ → QQ 手动操作，不会把 QQ 消息自动发回 Discord。

### QQ 定时消息

管理面板的「定时消息」卡片可设置消息内容、重复方式、发送时间和启用状态；每条消息可附加一张 PNG、JPEG、GIF 或 WebP 图片，也可只发送图片。图片单张不超过 2 MiB，所有定时消息图片合计不超过 3 MiB。附件保存在定时消息配置中，会随普通配置备份导出和恢复，导出 ZIP 仍受 5 MiB 上限约束。
重复方式支持“每隔 N 天”或“每 N 周指定星期”（可设置起算日期）。**发送目标按每条消息单独配置**，卡片内有“发送目标”一行：
- **指定群**：点「管理」勾选若干已审核的 QQ 群；未勾选任何群时沿用默认目标，不会阻止保存；
- **转发组**：引用「QQ → QQ」页的转发组，发送时动态取该组当前成员（组内增删群后自动跟随），被暂停的组不生效；此模式必须至少选择一个转发组；
- **全部群**：发送到所有已启用的 QQ 群，无需再选。

编辑器已不再显示「发送目标群」栏；`scheduled_message.target_groups` 仍是后端**默认目标**，所有切到“指定群”但未单独勾选的消息都发往它（新装环境为空时请为每条消息显式选择群或转发组）。任何模式下都只有同时启用的群会接收消息。消息卡片右上角的折叠按钮可单条折叠/展开，也可用「全部折叠」「全部展开」；卡片右下角为删除按钮（走原确认流程）。折叠只影响当前编辑界面，不改变保存内容。修改后无需重启机器人。白名单用户也可以私聊机器人使用
`/定时消息` 查询、`/定时消息 开启/关闭` 开启或关闭，或 `/定时消息 清空` 关闭并清空定时消息内容；消息内容、
目标群、重复方式和发送时间请在管理面板中设置。

### 公告自动翻译（可选）

管理面板的翻译默认全部关闭。「QQ → QQ」页提供一张共享「自动翻译」卡片：
首选与后备服务由全项目共用，卡片左下角的「翻译链路」按钮打开二级窗口，
其中 Discord、X、Bilibili、YouTube、手动转发五个整行胶囊开关分别批量启用或关闭对应链路
全部来源的翻译。Discord 频道、X 账号和 YouTube 频道仍可在各自来源表格中通过翻译图标
打开「翻译设置」窗口，用同样的胶囊开关单独设置是否翻译、是否保留原文和是否显示时间；
Bilibili 来源由该窗口的链路开关统一控制。Discord/X 手动转发沿用来源的
保留原文与显示时间设置，但不受来源自动翻译开关影响；纯 QQ 与 Bilibili
手动转发使用共享翻译开关和默认格式。YouTube 自动投递翻译时跳过来源头，
只翻译标题和链接所在正文。
服务不再单独设置启用按钮：选中的主服务和
失败后服务会按配置自动尝试，未配置或调用失败时继续发送原文。
AI 服务采用 OpenAI 兼容接口，可填写百炼、DeepSeek 等服务的地址和模型名；
密钥也可在面板的「翻译服务配置」中填写，或手动写入 `.env.prod`：
本机 Ollama 可填写地址 http://127.0.0.1:11434/v1、本地模型名（如 qwen3-4b-local:latest）和任意非空密钥值（例如 ollama；Ollama 本机服务会忽略该密钥）。
WRelay 会将本机默认 11434 端口请求转到原生聊天接口并关闭 thinking，清理 Qwen 输出中的思考标记；
冷启动模型时翻译至少等待 90 秒（档案超时设得更高时按配置等待），面板连通性检测最多等待 120 秒。
建议保留腾讯 TMT 等后备服务，避免本地模型未启动或请求失败时影响消息投递。
AI 配置的请求超时必须为 1–300 秒，最大输出长度必须为 1–1,000,000 tokens；超出范围的配置不会保存，损坏的 `settings.json` 在修复前会按安全默认值运行并保留原文件。

```text
WRELAY_AI_API_KEY=你的AI密钥
WRELAY_TENCENT_SECRET_ID=你的腾讯云SecretId
WRELAY_TENCENT_SECRET_KEY=你的腾讯云SecretKey
```

- 获取腾讯密钥：登录[腾讯云 API 密钥管理](https://console.cloud.tencent.com/cam/capi)，
  进入「访问管理 → 访问密钥 → API 密钥管理」并点击「新建密钥」。腾讯云只会在
  创建时显示 SecretKey，请立即保存；也可以直接在面板「翻译服务配置」中填写，
  面板会安全写入 `.env.prod` 并重启机器人。
- 开启共享卡中对应链路的翻译开关后，仅以外文为主的消息会被翻译；主服务失败会按该链路中的
  后备服务设置降级，所有翻译服务不可用时仍发送原文。
- 面板「翻译服务配置」中的「检测当前 API」和「检测全部 API」只检测保存的 AI 配置，
  不会触发运行时自动轮换；检测记录只显示类型和原因。窗口顶部的「当前工作模型」
  表示机器人最近一次真实翻译成功使用的模型，因此可能与检测记录不同。
- AI API 遇到 400 模型不存在/不支持、模型并发受限的 429，或明确表示模型容量/节点
  不可用的 500/503 时，会查询服务商的可用模型并按优先级逐个轮换尝试，直到成功或
  全部候选模型失败。普通网络超时、
  普通配额 429、空响应和未指向模型的服务端错误不会轮换。
- 腾讯 TMT 的文本接口可用性以腾讯云控制台和账号实际权限为准；建议同时配置 AI 后备。
- AI API 仅用于转发消息翻译；WRelay 不提供 QQ AI 对话，也不会把 QQ 消息
  自动发送到 Discord。

如果 AI 检测提示「响应内容为空」，表示接口返回了响应但没有提供可用的
`choices[0].message.content` 文本，不等同于模型不存在；可检查服务商响应格式、模型权限
和输出长度设置。

## 7. 网络与代理

Discord 用途需要本机能访问 Discord API、Gateway 和 CDN。若本机代理软件提供 HTTP／混合端口，可在 `.env.prod` 设置 Discord 适配器支持的 `DISCORD_PROXY`，例如 `DISCORD_PROXY='http://127.0.0.1:7897'`；请将端口替换为代理软件当前监听端口。该设置作用于 Discord API/Gateway、Discord 域名上的媒体下载、X/Twitter 媒体 CDN（`pbs.twimg.com`、`video.twimg.com`），以及 YouTube 频道 RSS 与封面下载。

若 `DISCORD_PROXY` 指向本机端口而该端口已不可用（例如代理软件重启后换了端口），Bot 启动时会自动改用 Windows 系统代理的当前端口并写入日志；代理软件未运行或系统代理也不可用时仍按原值连接。Discord 网关启动失败后会在约 24 分钟内按退避持续重试（15／30／60／120 秒，之后每 5 分钟一次），每次重试前重新检查代理端口；重启电脑后代理软件比机器人晚就绪也能自动恢复，连上即停止重试。切换端口时会同时更新 Discord 网关、补发抓取与媒体下载共用的代理配置，已缓存的 HTTP 客户端会在下次请求时按新端口重建，因此网关恢复后补发不会继续走旧端口。

程序会清除 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及小写形式；Bilibili 等非代理媒体下载仍使用系统路由，可在代理软件中启用可用的 TUN 虚拟网卡。YouTube 的 RSS 与封面请通过 `DISCORD_PROXY` 或 TUN 路由访问。设置代理后重启机器人，再在向导刷新连接状态。面板的「从全部可读频道注册」会运行 `scripts/diagnose_channels.py`，同样使用 `DISCORD_PROXY`；扫描提示无法连接 Discord 时，先核对代理端口是否仍与代理软件一致。

X/Bilibili 用途需要可访问所填 RSSHub 服务，其上游账号、Cookie、网络与路由仍由 RSSHub 服务负责。检测失败时按向导提示检查服务，再重试。
向导检测 Bilibili 来源时若收到 HTTP 503，请先核对 UID、标签或关键词，并查看 RSSHub 对应请求日志；常见原因包括上游请求被拒（可能显示 412），标签／关键词及部分动态路由还可能缺少 Chromium 支持。只有日志明确提示登录或 Cookie 问题时，才需要为 RSSHub 配置 Cookie。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 面板提示找不到运行环境 | 源码模式先运行 `install.bat`；安装包模式确认随包的 `python\` 目录完整 |
| 桌面窗口无法打开 | 确认 WebView2 Runtime 已安装，并查看 `data/logs/desktop.log` 中的启动错误 |
| 双击 WRelay 快捷方式没有窗口 | 若桌面进程仍在后台但已没有主窗口，快捷方式会通过本机管理管道请求重启桌面端；此操作不会停止机器人。若自动恢复失败，请查看桌面进程的启动提示和 `data/logs/desktop.log` |
| 机器人启动、停止或重启失败 | 查看面板提示和「运行日志」；编译安装版在日志系统启动前退出时，查看 `data/logs/bot-startup.log`；启动失败时确认 `.env.prod` 的 token / AppID / AppSecret；若 PID 文件写入失败且新进程仍在运行，可在面板再次点「停止」；PID 校验会核对进程创建时间以避免系统复用 PID，停止时会轮询确认进程退出。若提示无法确认 PID 状态，请以启动机器人的相同 Windows 权限运行管理面板；若 `data/bot.pid` 不可读或格式损坏，先检查并修复该文件，面板会保留现场并阻止重复启动 |
| 备份导出或恢复失败 | 导出和导入 ZIP 上限均为 5 MB；数据超限时请取消包含运行状态。运行状态备份包括游标、重试队列、X/Bilibili/YouTube 跨来源去重数据库和 YouTube 频道状态/保护队列；恢复前先停止机器人，运行中会拒绝恢复，以免进程内状态覆盖恢复文件。恢复失败时服务会尝试恢复到操作前状态；若提示自动回滚不完整，请保留提示中的恢复前 ZIP 并查看面板运行日志，先不要再次恢复 |
| 收不到转发消息 | 群主是否开启「主动消息」权限；公域机器人有时段/频率限制；频道 ID / 群 openid 是否已启用 |
| Discord/X/Bilibili/YouTube 旧消息重复补发或去重状态读取失败 | 检查运行日志中的 `discord_last.json` 错误；损坏的去重游标会被保留且相关自动投递/补发会暂停。先停止机器人，再从备份恢复 `data/discord_last.json`，然后重启 |
| 延迟重试队列读取失败 | 查看运行日志中的 `retry_pending.json` 错误；原文件会保留，新失败消息改由 Discord 补发兜底。先停止机器人，再从备份恢复 `data/retry_pending.json`，然后重启 |
| 图片 / 音频发不出来 | 检查代理；文件超过 `MEDIA_MAX_BYTES` 会降级为文字 + 链接 |
| 「从全部可读频道注册」提示无法连接 Discord | 该扫描使用 `DISCORD_PROXY`，不会读取已被清除的 `HTTP_PROXY`。核对 `.env.prod` 中的代理端口与本机代理软件当前 HTTP／混合端口一致后重试；也可改用 TUN 路由并删除该行 |
| 视频发不出来 | 检查媒体下载权限、代理和文件大小；下载/上传失败时会保留视频链接，详情可在消息追踪查看 |
| RSSHub 请求失败 | 查看 X/Bilibili RSS 状态卡片和运行日志；429/5xx 会自动短暂重试，持续 502 通常需要检查 RSSHub 服务本身 |
| YouTube 来源拉取失败 | 频道 ID 需以 `UC` 开头，`@handle` 需能从频道主页解析；确认 `DISCORD_PROXY` 或 TUN 路由可访问 `youtube.com`。官方 RSS 只支持频道，不支持搜索、关键词或播放列表来源；HTTP 404 表示频道不存在或已关闭 RSS |
| QQ Bot 一直显示未连接，日志出现 `httpx.InvalidURL: Invalid port: ':1]'` | 系统代理绕过列表含方括号 IPv6 条目（如 `[::1]`）。启动时会自动移除这类条目；若仍出现，请在「Internet 选项 → 连接 → 局域网设置 → 高级」中删除该绕过项 |
| 启动后向 QQ 群补发大量历史消息 | 启动补发会补投“上次记录的游标之后”的消息。若数据目录被更换或游标过旧，缺口会被视为离线积压。可在面板调整补发条数上限或关闭启动补发；更换数据目录时先同步 `data/discord_last.json` 等游标文件 |
| 状态卡长时间显示“等待 RSSHub 启动” | 说明启动宽限期内 RSSHub 仍不可达。先在本机访问 `http://127.0.0.1:1200`（或所填地址）确认服务已监听；若 RSSHub 由 Docker 提供，确认 Docker Desktop 已启动且容器为 `Up`，再等待容器完成启动 |
| 开机后 RSSHub 一直不可用 | Docker Desktop 与 RSSHub 需要随登录自启。若容器曾被手动 `docker stop`，`restart: unless-stopped` 不会自动拉起它，需要手动 `docker start rsshub` 或 `docker compose up -d` |
| 想重置配置 | 删除 `data/settings.json` 后重启机器人，会生成空配置重新开始 |

## 9. 卸载与数据保留

- 升级时先退出桌面程序并停止机器人，再运行新的 `WRelay-Setup.exe` 并选择原安装目录；不要先卸载旧版本。安装器会检查桌面单实例锁，并尝试关闭正在使用的已安装程序文件。
- 升级前建议备份 `data/` 和 `.env.prod`。升级会覆盖程序文件，但默认保留用户数据和配置。
- 旧版本如果安装在早期的 `Program Files` 目录，不会自动迁移到当前用户目录；请先备份数据，再按新目录安装并手动迁移需要的配置。
- 从源码目录迁移到安装版时，先停止源码机器人，再复制 `.env.prod` 与需要保留的 `data/` 配置和运行状态；不要复制 `bot.pid`、锁文件或旧日志。已有源码版开机启动项会在安装时改指向新的 WRelay.exe。
- 卸载程序默认保留 `data/` 和 `.env.prod`，包括频道配置、去重游标、重试队列、面板认证信息和机器人凭据。
- 这样可以避免卸载或升级时误删运行状态；重新安装到同一目录后可继续使用原配置。
- 如果要彻底移除 WRelay，请先卸载程序，再确认不需要这些数据后，手动删除安装目录中残留的 `data/` 和 `.env.prod`。
- 删除前请注意：`.env.prod` 含机器人密钥，`data/` 含运行配置和身份资料，建议先备份或使用安全删除方式。

## 10. 安全提醒

- `.env.prod` 含密钥，**绝不提交、不分享**。
- `data/` 目录是运行时数据（配置、去重记录、重试队列、消息追踪、日志），误删会丢失运行状态，
  但不影响程序本身；`data/panel_auth.json` 不应外传。
- 失败消息会持久化到 `data/retry_pending.json`，进程重启后继续重试；媒体文件本身不会写入该文件。
- `data/message_trace.json` 只保存最近投递追踪摘要，不保存媒体字节；可在面板消息追踪窗口查看。
- 自动链路为 Discord → QQ、X RSS → QQ、Bilibili RSS → QQ 和 YouTube RSS → QQ；不做 QQ → Discord，QQ → QQ 仅限授权用户手动命令。


### 桌面关闭偏好与托盘验证

“每次询问”的原生对话框提供收起到托盘、退出桌面端和取消，不会修改已保存的偏好。“停止机器人并退出…”另用危险确认，取消不停止机器人；普通退出移除托盘图标。重启管理程序保留机器人当前运行/停止状态，包括通过 Windows 自启启动的桌面管理程序；旧窗口若无法正常关闭，重启流程会在 8 秒后强制结束旧桌面进程，机器人继续运行。关闭偏好在桌面窗口配置。

开发验证使用 `scripts/test_desktop_controls.py`（14 项隔离偏好/菜单/操作与重启分支测试）和 `scripts/test_desktop_controls_native.py`（透明、不显示任务栏的 WinForms 对话框测试）；均不启动真实机器人。测试需使用安装了桌面依赖的 Python。完整窗口验证可运行既有 `scripts/test_desktop_titlebar.py`，其 WebView2 初始化失败时不能视为通过。

### 无需 Agent 的长期运行维护（0.1.1）

1. 在设置开启「随 Windows 启动」，关闭窗口选择收起到托盘，并保持电脑通电联网、不睡眠。当前自启在用户登录后执行。
2. 「自动备份与维护」默认每小时保存并校验一份含运行状态的备份，保留 30 份。第一次在后台完成；再次启动沿用最近有效备份时间。可立即备份，也可关闭自动备份。
3. 维护告警在主窗口和设置页显示。RSS 来源连续三轮失败、队列/游标文件损坏、去重数据库异常及自动备份失败均可提醒；QQ 提醒需开启「失败通知」并给已授权白名单用户勾选「告警」。QQ 断线时无法送达，重新连接后会尝试。
4. 恢复时选择标记「已校验」的自动备份并确认。程序重新检查清单、哈希、配置、JSON 状态结构和数据库，然后停止正在运行的机器人，保存恢复前副本并恢复；成功后恢复原来的运行状态。无效备份不会用于恢复，失败时保留旧备份与回滚文件。旧 v1 手动备份没有哈希，但仍需通过结构校验。旧备份恢复可能重复投递或漏发，请选择故障前最近一份。
5. 自动备份保存于安装目录 `data/auto_backups/`；恢复前副本保存于 `data/restore_backups/`。备份不含机器人、翻译服务密钥；新电脑仍需填写账号凭据。ZIP 与解压内容上限均为 5 MiB，超限会告警，不会删除原有有效备份。
6. 独立桌面看护会恢复异常退出或管理接口持续无响应的桌面程序，保持正常停止/退出意图。反复启动失败时 10 分钟内最多恢复 5 次，详情查看 `data/logs/guardian.log`。Windows 注销/关机、手动结束整个进程树或机器休眠期间不会继续工作。

自动备份只保护本机可读取的文件，不会擅自清空或静默回滚损坏状态。建议定期将导出的备份另外保存到其他磁盘。
