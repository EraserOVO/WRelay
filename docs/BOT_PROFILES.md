# 每个 Bot 的来源、转发组与配置导入

官方 QQ Bot 和个人 QQ 都使用独立配置文件。先在页面上方选择账号，再编辑、导出或上传；修改一个账号的来源开关、筛选、来源翻译和转发组，不会修改其他账号的同名来源。

## 文件与归属

- 官方 Bot：`data/bot_profiles/official_<AppID>.json`。
- 个人 QQ：`data/bot_profiles/personal_<QQ号>.json`，接口账号标识为 `personal:<QQ号>`。
- 文件格式为 `wrelay-bot-profile`、版本 `1`，包含账号标识和 `config`。
- 每个文件包含 Discord/X/Bilibili/YouTube 来源、五条链路的转发组，以及各自的轮询地址、间隔、投递保护、Discord 补发与 Bilibili 自动解析设置。
- `data/settings.json` 保存账号文件索引 `bot_profile_ids`、群注册及绑定、用户授权、定时计划、翻译服务和其他全局设置。官方及 Discord 凭据仍在原来的凭据配置中；个人连接令牌仍在 `data/personal_qq.json`。

接收群的注册和账号归属继续集中管理，自动路由只接受当前账号拥有的群。授权手动 QQ → QQ 仍支持原有明确配置的跨账号目标，不扩展为自动同步。定时计划保持全局，迁移不自动复制计划；沿用原计划的投递身份，避免创建重复任务。

## 导出和上传

1. 选择来源账号，点击总览页停止按钮左侧的文件按钮，选择「导出配置」，在另存为窗口选择本地位置。
2. 选择目标账号，在总览页文件按钮中选择「上传配置」，选择导出的 JSON，最大 5 MiB。
3. 默认「合并」：已有同标识来源保留目标值，导入组使用稳定的新标识；重复导入同一文件不会重复添加同一组。轮询、保护和补发等链路设置保留目标值。
4. 「替换」只替换目标账号的来源、转发组和链路设置，其他账号和全局授权、计划不变。
5. 为文件中的接收群逐项选择目标账号已经注册的接收群。官方 OpenID 不能当作另一 Bot 的 OpenID；个人群也不能通过导入抢占另一个账号的绑定。缺少对应关系的组会暂停，必须配置完整后自行启用。
6. 点击「预览」，检查前后数量和提示，再点击「确认导入」。修改文件、方式或群对应关系后必须重新预览；预览后配置发生变化也会拒绝提交，防止覆盖其他操作。

导出文件不包含 Bot 密钥、个人连接令牌、用户授权、定时计划、历史投递记录或运行队列。来源可访问性仍取决于当前 Discord/RSS 连接。导入不发消息，不清空投递记录，也不触发历史补发；新来源沿用各链路现有的安全基线规则。

## 升级、隔离与恢复

首次启动新版机器人，或面板首次打开已选择账号的配置时，按现有群归属拆分旧配置。原始 `settings.json` 留在 `settings.json.before-bot-profiles.json`；原来源标识、转发组标识、频道 × 接收群游标和投递去重数据库保留。旧 RSS 缓存与队列复制到对应账号的 `data/bot_profile_runtime/<配置文件名去扩展名>/`，原文件保留。无法归属且没有官方默认账号的配置保存在 `unassigned.json`，不参与自动投递。

恢复旧版配置后再次迁移时，已有迁移备份不覆盖；不同内容追加摘要命名的迁移副本。已经存在的账号运行文件保持原样，避免普通配置恢复覆盖较新的队列和缓存。

升级后重新启动桌面端和机器人，以加载新的账号配置读取逻辑。普通配置修改及导入后，运行中的新版机器人会读取新值；不需要为导入主动重启或补发。

RSS 轮询缓存、积压和限速时间窗按账号分开；现有轮询器按账号依次执行，单账号的一轮失败不会阻断其他账号后续执行。Discord 实时消息、补发和延迟重试都在接收账号的配置范围内读取筛选。空组列表保持为空，不自动生成全量投递路由。损坏的账号配置暂停该账号，其他完好账号继续。

保存账号配置前保留对应 `.json.bak`，文件原子替换；写入全局设置失败时回滚本次账号文件。保存时校验全局文件及所有账号文件的版本。不要在机器人运行时手工覆盖文件。

面板状态接口带 `bot_id` 时显示当前账号；后台维护的无账号状态请求汇总所有账号的来源健康与队列告警，继续保留原有维护提醒。

完整 ZIP 备份始终包含索引引用的全部账号文件；选择包含运行状态时，也包含各账号的 RSS 运行文件。恢复先校验完整性、账号归属及路径白名单，保留恢复前副本，先恢复账号文件再提交索引。运行状态恢复继续要求停止机器人并确认。单账号迁移请使用上面的 JSON 上传，整机恢复使用原有 ZIP 备份入口。

## 维护入口

- `plugins/bot_profiles.py`：归属、迁移、快照、版本和原子保存。
- `plugins/profile_runtime.py`：串行切换 RSS 账号缓存及运行文件，取消时等待在途工作结束再切换。
- `panel/profile_api.py`：`GET /api/bot-profile/export?bot_id=…`、`POST /api/bot-profile/import?bot_id=…`，导入先预览后确认。
- `panel/web/bot-profiles.js`：下载、文件上传、群对应关系及预览确认。
- `scripts/test_bot_profiles.py`：临时目录中的迁移、隔离、导入和备份恢复检查，不连接真实 QQ 群。

维护检测与备份恢复共用主配置校验：分文件模式只为已经迁出的字段补齐校验视图，全局字段的错误类型仍报错；每份账号文件单独校验格式、版本和账号归属，索引引用的文件缺失也会告警。账号运行文件按原始状态文件名套用队列和游标规则。检查只读，修复文件后下轮检查清除对应告警。
