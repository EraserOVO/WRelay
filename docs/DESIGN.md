## 桌面端窗口布局

以下模板说明以当前代码为准；后文按日期记录的阶段方案保留为历史，以末尾“根滚动条稳定与全局日志归位”为最新规范。

### 共用功能页模板（以 Discord → QQ 为基础）

四个桌面转发页统一采用“顶部运行状态（含 RSS 状态）→ 转发组 → 下方其他卡片”的顺序，机器人状态卡与 RSS 状态卡之间、顶部状态区与下方转发组或首张卡片之间的间距均为 16px，由顶部容器的 gap 与外间距分别控制，状态卡自身不再叠加下边距。下方卡片按从左到右、再从上到下排列，使用手动转发卡的两列宽度与 164px 最小高度；Discord 的离线补发排在手动转发卡下方，Bilibili 的手动转发卡位于左列。最近消息卡仅在总览显示。顶部只保留运行状态、当前 Bot、PID 与转发统计。QQ 用户白名单集中在设置页“机器人与服务”中的标准设置行，管理表格在二级弹窗中打开，供 Discord、X 和 Bilibili 链接手动转发共用。进程启停与重启仅保留在总览；备份、诊断、失败通知、Windows 启动、管理程序重启及关于作者入口统一在设置，四个功能页彻底删除运行工具 Card。

转发组沿用现有 Tab 与组级操作栏、固定布局表格、ID 截断/复制、危险图标按钮、拖动排序及空状态。配置向导位于设置页“应用”卡片末行；“外观与窗口”中“界面动画”排在“界面主题”上方；设置行右侧文字按钮与跳转链接共用页面字体、14px 字号和 20px 行高。两栏底部同一紧凑 footer 左侧放新增/注册，右侧使用公共 `.linkbtn` 外部入口和配置按钮。窄窗口继续沿用单栏断点。白名单新增/审核集中在设置页设置行，通过二级弹窗管理，功能页不再重复显示；手动转发与翻译使用分隔线设置区。补发、翻译和日志自动滚动复用 `.settings-switch-track`，提供 `role="switch"` 与实时 `aria-checked`，原保存流程不变。

四个功能页不显示全局日志。统一入口为“设置 → 启动与维护 → 运行日志”，使用标准 ModalShell：最高 320px 的深色等宽控制台内部滚动，正文下方放级别/消息追踪/自动滚动 Toggle，底部右侧放复制/清空。根 HTML 预留稳定滚动条空间，切页与折叠不改变可用宽度。

机器人状态卡与 X/Bilibili RSS 状态卡在正常运行时显示低对比度渐变扫光，适用于总览及各转发页的深浅主题。设置 → 外观与窗口提供“界面动画”开关，默认开启；偏好保存在本机 localStorage，并立即作用于所有页面。扫光采用低饱和蓝灰色（深色主题 #9fbfd6、浅色主题 #7e9fb9），柔和的斜向光带从左向右扫过卡片，每 8 秒循环一次，扫过后短暂停留在卡片外；不再显示波浪与气泡。机器人动效要求进程运行、当前 QQ Bot 已连接；Discord 与总览还要求 Discord 已连接。RSS 动效沿用现有绿色“运行中”判定；停止、等待连接和请求/解析失败时不显示。装饰层位于内容后方，不拦截点击，也不改变卡片尺寸和间距；系统启用“减少动态效果”时隐藏扫光。

`panel/web/discord-page.js` 保留原文件名，现为四个功能页共用的展示适配层：按页面配置选择工作区；移动现有控件而非复制控件，跨页切换先还原再安置。QQ 用户白名单由设置页入口打开独立弹窗，不随当前链路搬移。样式复用 Discord 的同一组规则，总览和设置页不采用紧凑功能页模板。表格行、复制、拖动、保存和配置弹窗仍沿用原处理函数。

X 和 Bilibili 使用相同的 RSS 状态区：标题独占首行，徽标与来源/轮询/投递统计同行，地址与间隔位于下一行。状态、来源、上次轮询、发现、发送、地址及间隔保留，Bilibili 另保留积压与保护设置。异常时保留统计信息，错误原因和普通统计分别着色。工作区采用与 Discord 相同的双栏、底部新增/注册与外链左右排列结构；1280px 及以下转为单栏。Bilibili 来源注册仅收集来源范围及其 UID、标签名或关键词；列表和已注册来源弹窗直接显示该值，不提供自定义备注。Bilibili 转发组来源表仅展示类型和来源名称，筛选条件通过来源行漏斗按钮及“消息筛选”二级窗口查看和编辑，不在表格中重复显示文字摘要。筛选窗口布局沿用 X：上方按关键词筛选，下方选择投稿类型；UP 主来源支持视频、专栏、动态，标签与关键词来源仅支持视频，视频本体转发开关也放在此处，并以胶囊开关呈现。来源筛选不再提供额外标签、作者或标题条件。手动转发卡从下方双列卡片区的左列开始，最小高度 164px，并保留说明和底部操作栏；说明文字采用与 X 相同的单句格式，短链接与视频发送细节放在帮助提示中；1280px 及以下铺满页面宽度。卡片提供已注册来源弹窗和独立消息类型筛选。QQ 白名单仍由总览或设置统一管理。三页 Tab 较多时仅标签条横向滚动，组操作不换行。

QQ 定时消息改为紧凑设置区：空状态提供“+ 新增”，有任务时显示数量摘要和编辑入口；启用定时发送使用 Toggle，实际仍打开原定时任务编辑器。各功能页顶部徽标只描述进程“运行中/已停止”，Bot 下拉框独立描述连接状态，RSS 徽标保留原运行/等待/错误判定。总览与各功能页的机器人状态徽标，以及 X/Bilibili RSS 状态徽标统一采用 36px 最小高度和 4px 9px 内边距；不修改后端状态判断。

全局 Bot 与翻译服务配置统一在设置页，直接使用 `btnDiscordConfig`、`btnQQConfig`、`btnTranslationConfig`，不再通过功能页的隐藏按钮代理；原功能页重复配置按钮已删除，链路翻译启用、路由与来源级配置仍保留。

三页验证使用隔离示例数据，所有写请求被测试预览拦截：1366×768、1920×1080、2560×1440 及各自 125%/150% 等效内容视口，共 27 组布局检查无页面横向溢出或表格按钮裁切；双栏等高、窄窗口单栏。配置弹窗、定时任务空/非空入口、日志折叠和运行工具、断连及 RSS 错误展示已检查。未触发真实机器人启停、转发、补发、保存或删除；等效视口验证不代表完成系统 DPI 切换测试。

### 总览与公共外壳

总览页使用紧凑的横向机器人状态栏、2×2 转发链路卡片和单行最近消息；主题切换统一从设置页进行。Windows 标题栏使用独立的原生窗口模块绘制：高度 38px、Logo 24px、三个窗口按钮各 46×38px，尺寸随 DPI 缩放；关闭按钮悬停为 Windows 风格红色，最大化时自动绘制还原图标。窗口拖动、双击、系统命令、Snap 和边缘缩放通过原生消息处理，关闭行为由持久化桌面偏好决定，默认收起托盘。

桌面端首次打开进入运行总览，集中展示机器人控制状态、各转发链路的运行状态和配置数量，并提供进入对应管理页的快捷入口。左侧保留 Discord → QQ、X → QQ、Bilibili → QQ、授权 QQ → QQ 手动转发和设置导航。

侧栏 6 个导航图标与总览 4 张链路卡统一采用 MingCute 的 line 版 SVG：`home_1_line`、`discord_line`、`social_x_line`、`bilibili_line`、`qq_line`、`settings_1_line`。Discord、X、Bilibili、QQ 在导航和总览中复用相同路径；图标使用单色 `currentColor`，保留现有图标槽、卡片背景和导航布局。MingCute 使用 Apache 2.0 许可。
浅色主题下，总览四个链路图标使用浅色品牌底色，并保留足够的图标前景对比度；深色主题沿用原配色。

设置页单独管理桌面主题、应用版本和手动更新检查。更新检查读取 GitHub 最新稳定发行版；用户可打开发布页下载安装，不会静默下载或安装。机器人账号、翻译服务、启动方式、备份和诊断作为独立的维护区域保留。桌面端首次进入运行总览，并记忆当前页面。

桌面页面使用统一的颜色、间距、圆角和控件尺寸变量。各页标题与说明共用主内容对齐线；总览隐藏非必要的标题栏快捷操作，机器人统计和启停按钮紧凑排列，窄窗口时导航收为 60px 宽的图标栏，导航起点与普通侧栏顶部对齐，图标在侧栏内居中，隐藏的文字标签不保留额外间距。转发组操作集中在组标签右侧。

模块标题使用清晰的中性色，蓝紫色用于导航、主操作和选中状态。转发组暂停状态以中性标签表达，当前组仍使用统一的品牌选中态。桌面配置入口以设置行呈现；外部链接按钮共享相同图标、尺寸和次级层级。机器人状态区的 PID 与转发统计采用一致的字段和值层级，并将随 Windows 启动显示为开关。

桌面按钮悬停反馈按用途分组：普通次级操作与外部链接统一使用轻微底色、边框和文字对比变化，并平滑过渡；设置中的“发布页面”和“关于作者”保持相同边框反馈。设置开关只高亮外壳，保留开关轨道的开/关颜色，悬停和键盘聚焦时不弹出文字提示，仍保留无障碍名称；主操作继续使用简洁反馈，危险操作保留危险色，禁用按钮不响应悬停。图标工具、帮助和折叠按钮保留各自紧凑的专用反馈。

转发频道、来源、接收群和白名单表格共享行高、复选框和操作按钮样式。列宽按卡片可用宽度分配，不使用强制最小宽度；长 ID / OpenID 省略显示、悬停查看完整值并提供复制按钮。窗口变窄时转发列表改为单栏，更窄时隐藏次要的 QQ 账号列。日志保持固定高度并在内部滚动，可复制或清空，并能切换自动跟随；页面主体保留主要纵向滚动。

长 OpenID 显示头尾片段，复制仍使用完整值；复制成功会短暂显示勾号。表格删除操作默认使用低饱和图标，悬停或键盘聚焦时再显示危险色。总览中的 RSS 状态与来源数量分开呈现，机器人状态标题采用圆形 Help 图标，统计分隔线弱化。四张链路卡使用统一的 Chevron 和三行文字基线，保持 2×2 布局与原有紧凑高度。最近消息中的链接预览优先显示域名，摘要占剩余宽度并省略，时间固定右对齐；“更多”采用可键盘操作的文字入口，悬停仍可查看完整内容。导航仅当前页面具有 active 与 aria-current，普通 hover 采用弱中性色。

QQ → QQ 的定时消息设置区在空状态时说明尚未配置，并提供添加入口。

总览最终微调：标题至首卡片、状态区至运行概况、链路区至最近消息的间距各增加 6px，不增加卡片高度。机器人信息区在常用宽窗口约占整卡 60～65%，较窄窗口优先保证字段可读；Bot 下拉框上限 210px，为箭头预留 32px。链路第二行将绿色状态词与灰色说明分开，QQ 使用“已连接 · 授权手动转发”，避免重复状态。最近消息摘要及“更多”使用普通字重和较弱文字层级，字号保持不变。

### 标题栏验证

在 Windows 开发环境运行 `.venv\Scripts\python.exe scripts/test_desktop_titlebar.py`，使用透明、非聚焦且无任务栏入口的独立 WebView2 窗口检查标题栏装配、DPI 尺寸、四边四角与窗口按钮命中区域、标题栏双击原生消息、内容避让、主题切换、最大化/还原图标与关闭取消流程，并检查重复最大化/最小化后还原尺寸不漂移、普通尺寸调整仍生效。不启动机器人或管理 API。

添加 `--interactive` 可打开独立可见测试窗口，显示实际 DPI 和内容视口。自动命中测试不替代真实鼠标拖动：标题栏拖动、八方向实际拖动、Snap 悬停菜单与跨屏 DPI 切换需要交互复核。保留的最小窗口尺寸可能限制较窄的 Snap 区域。此次实际环境为 125% DPI；150% 只检查对应内容视口，尚未完成系统级 DPI 切换验收。

### 全局组件与键盘交互精修（2026-09-26）

本轮保持四页工作区布局、API、数据结构和转发逻辑。模块状态区统一间距、控件高度与分隔线；QQ 定时消息标题与空状态左对齐，添加及启用控件靠右，窄窗口自然换行。定时消息编辑器无数据时提示下一步操作。内层来源/群 Pane 降低背景对比，保留现有双栏和背景结构。

- Help 按钮统一为 SVG 图标，复用 `discord-page.js` 中的单个 Tooltip，支持鼠标悬停、键盘聚焦与 Esc 关闭；点击仍打开原说明弹窗。动态表格按钮从现有动作标题读取提示，复制和配置提示明确操作对象。
- 按钮、Tab、Checkbox、Switch、输入框、下拉框和外部入口共享品牌色 focus-visible。行内名称编辑图标新增键盘焦点，Enter/空格沿用原编辑入口。
- ID/OpenID 保持截断、完整 title 和复制按钮；聚焦 ID 或复制按钮时 Ctrl+C 走原复制函数。有文本选择时不拦截系统复制。
- Ctrl+S 只在有保存按钮的编辑弹窗、名称编辑框或已有即时保存参数框中处理；普通输入和页面不再全局保存。Esc 沿用弹窗关闭并支持 Tooltip；输入法组合键不触发这些快捷键。
- Delete 仅在聚焦转发组/白名单删除按钮且没有弹窗时触发原确认流程。启用复选框不表示删除选择；其他移出操作没有自动增加 Delete 快捷键。
- 停止/暂无数据使用中性灰徽标，等待/未连接和投递待处理为橙色，成功为绿、错误为红。四个功能页的进程状态与当前 Bot 连接状态独立展示；RSS 判定优先级不变。
- 删除和清空默认弱化，hover/focus 加强；确认弹窗的删除/清空确认按钮使用危险色。外部按钮复用 `.linkbtn`，统一明确的平台名称。
- 折叠日志摘要使用等宽字体、单行省略；展开按钮固定，日志正文保持 220px，自动滚动保留 Switch。

验证：隔离示例数据下，四页在 1366×768、1920×1080、2560×1440 及各自 125%/150% 等效内容视口共 36 组检查无主页面横向溢出、表格按钮越界或重复 active 导航；QQ 定时区调整后单独复查九组尺寸。HTML 与运行中 DOM 未发现重复 ID，`btnQQConfig`/`btnXQQConfig` 仍分别绑定同一配置入口。检查 Help 聚焦/关闭、Enter 打开说明、Delete 确认、复制按钮反馈、表单 Ctrl+S 与普通区域不拦截、折叠/展开日志；快捷键逻辑另以隔离对象验证。预览请求全部由内存示例响应，不连接真实机器人；未执行真实投递或改动实际配置。

限制：本轮 DPI 检查使用等效浏览器内容视口，不代表 Windows 系统 DPI 切换和真实 WebView2 全部快捷键验收。后续最终交互验收补齐弹窗焦点与移出/清空确认，见下节；未扩展为批量选择删除或重构弹窗体系。
