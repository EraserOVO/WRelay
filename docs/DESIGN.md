# WRelay 设计概念图

总览页停止机器人按钮左侧提供同尺寸的文件图标按钮，点击后选择「导出配置」或「上传配置」；其他页面不显示该入口。桌面端优先使用原生保存窗口并显示保存路径，原生接口未就绪时回退到浏览器下载。账号切换重新加载该账号的来源与转发组，并立即刷新运行状态、RSS 状态、补发数量和最近消息；总览接收群数量按当前账号归属计算。来源、转发组、授权用户、手动转发筛选、定时计划和翻译路由按账号独立存储；新投递记录及 Discord 统计按账号显示，无法归属的旧记录不计入账号数据。翻译服务凭据仍为共享配置。
点击「上传配置」后直接打开文件选择器；选中文件后才显示简短的来源、群和授权用户摘要，并在「确认导入」后写入配置。桌面端优先使用原生文件选择器，原生接口未就绪时回退到 WebView 文件选择器；网页端使用浏览器选择器。
导出和上传菜单项直接绑定各自的点击操作；导出打开保存对话框，上传打开文件选择器。上传确认窗口的底栏使用独立容器，供公共弹窗组件迁移确认按钮，确保窗口其余控件保留在页面中。
弹窗使用标题栏 × / Esc / 遮罩关闭。全局凭据、账号授权、定时计划和翻译设置不随账号配置导出，详见 [Bot 独立配置](BOT_PROFILES.md)。

设置页的连接诊断、消息追踪、确认窗口与配置向导同样支持上述关闭方式；向导关闭时继续保存进度，配置窗口的保存和取消入口保持原有行为。

设置页新增「个人 QQ」二级窗口，沿用公共 Modal（中等宽度、正文滚动、右下保存、标题栏 × / Esc / 遮罩关闭）。
每个连接使用两列字段、整行状态和胶囊启停开关，支持接收群选择及待确认投递处理。
个人号与官方机器人共用工作区选择器，名称显示 QQ 号及启用状态；个人目标可进入 QQ → QQ 转发组及定时消息选择。
个人用户私聊 `/注册` 后以 `personal:<QQ号>` 进入现有白名单，默认关闭，管理员明确启用后才能管理和手动转发。
连接、令牌与未知结果的行为见 [PERSONAL_QQ.md](PERSONAL_QQ.md)。

本页保存 WRelay 项目概念图和桌面窗口布局参考。桌面程序采用 WebView2 窗口、左侧导航和托盘入口；图片中的占位条仅表达视觉结构，实际数据由桌面进程内的管理逻辑提供。

## 桌面端窗口布局

以下模板说明以当前代码为准；后文按日期记录的阶段方案保留为历史，以末尾“根滚动条稳定与全局日志归位”为最新规范。

### 共用功能页模板（以 Discord → QQ 为基础）

桌面端五个转发页统一采用“顶部机器人状态栏 → 转发组”的结构。Discord 离线补发由后台默认自动运行，管理面板不显示其状态卡片、详情窗口或手动操作按钮。X、Bilibili、YouTube RSS 与 Steam 状态可从顶部状态入口打开二级窗口；窗口复用对应状态卡片，关闭后恢复页面位置。QQ → QQ 页在最右侧按钮槽提供失败通知图标开关，其余操作槽保持预留。二级窗口高度随内容收紧，正文左右留出 20px 并与标题栏对齐；内容超过可用高度时只在正文内滚动。顶部机器人状态栏、转发组及其余功能卡片沿用现有统一布局规则。

QQ 定时消息卡片的标题从卡片内容区顶部起排，标题行保留相同的控件高度和帮助图标垂直居中；卡片其余内容继续使用各自布局。

转发组卡下方保留的功能卡片统一使用两列网格，间距 16px、1280px 及以下退化为单列，按从左至右、从上至下排列。QQ 定时消息、手动转发、自动翻译等卡片按网格规则排列；RSS 与 Steam 状态从顶部入口打开详情，不占用页面网格。

保留在页面网格中的功能卡片内部起排与按钮位置（长期有效）：卡片为 display:flex、纵向排列且间距为 0，标题在最上，可选的一句话说明紧随其后（顶部间距 8px），动作栏以自动上边距贴底并占满内容宽度；动作按钮从卡片左下角起排，成对图标动作才使用左右分布。胶囊开关默认贴左下角；详细说明写在标题旁帮助提示中，批量或次要设置通过入口打开二级窗口。

小卡片标题行统一为 36px 高、垂直居中，标题文字与问号在各卡片距顶位置一致；「自动翻译」卡的服务选择区与标题之间不绘制横向分隔线。

共享「自动翻译」卡同样只占网格中的一格，排在「手动转发」卡之后：卡内只有首选/次选服务两个下拉（窄格内自动换行）和左下角的「翻译链路」入口按钮。六条链路（Discord、X、Bilibili、YouTube、Steam、手动转发）的批量开关收进 `#translationChainsModal` 二级窗口（ModalShell `small`、无自定义页脚故自动生成「关闭」，与「已注册来源」同级），窗口内是一句话说明加六个上下排列的勾选式开关（圆角选项底、方框勾选在左、文字在右），点击仍走 `saveAndReload()` 保存并留在窗口内刷新状态；Discord、X、Bilibili、YouTube 和 Steam 的单个来源翻译选项统一在来源行「内容筛选」中设置，不再打开单独的来源翻译弹窗。Steam 来源提供是否翻译与是否保留原文两项；其他来源保留各自适用的时间设置。

转发组外层卡片在深浅主题下统一使用 `--card-bg` 与 `--panel-border`；来源和目标分栏使用独立的圆角表面，浅色主题以浅灰蓝底色和边框与外层卡片区分。表格中的名称、账号、来源值及 ID 在空间不足时以中间省略号保留开头和结尾。悬停或键盘聚焦任一值显示完整内容，右键复制完整值；键盘聚焦后按 Enter、空格或 Ctrl+C 也可复制，有选中文字时 Ctrl+C 保留原生复制。复制成功后提示固定在原位置显示 2 秒再淡出，使用 MingCute 勾选图标，值本身不变色。表格不再单独显示 ID 复制按钮。带外链的来源值左键打开原页面，右键复制链接文本。Steam 来源与接收群表格共享省略显示、复制和反馈规则。编辑输入保留原文。每个转发页的左右分栏折叠按钮成对同步，任意一侧展开或折叠时两侧内容、按钮状态和无障碍状态一致。

二级窗口统一规则（长期有效，适用于全部卡片二级窗口）：
正文中的文字按钮和勾选式开关按内容宽度显示，不因网格列被拉长；多个控件按内容排列，空间不足时换行。底栏的主要动作仍按下述规则贴右。
1. **内容网格式对齐**——`ui-components.js` 的 ModalShell 规格表用 `grid: true` 声明哪些窗口启用统一正文（当前为编辑定时消息、已注册频道、翻译链路、安全备份与恢复、运行日志、翻译设置、QQ/Discord 配置），`modalShell()` 据此给正文加 `.modal-grid`：单列起排、`justify-items: stretch`、行间距 14px，标题下每一行的左缘都与正文内边距对齐（基准是「已注册频道」的行式列表）。需要并排的容器加 `.modal-split`（等宽两列，内部 label 纵向起排），需要跨整行的元素加 `.modal-span-all`。旧窗口自带的内联底色/边框/内边距由 `body .modal-shell > .modal-body > div[style]` 统一失效，外观只由 `.modal-shell` 提供；「翻译服务配置」保留自己的两列正文。
2. **底栏左右分区**——`.modal-footer > button:first-child` 贴左下、`:last-child` 贴右下：主要动作（保存 / 确定 / 恢复配置 / 清空日志）一律右下角，取消、复制、上下文入口左下角；配置向导将「稍后配置／验证」「重新开始」并排放左侧，将「上一步」和主要动作并排放右侧。Discord Bot 与 QQ Bot 配置窗口左下角放的是平台外链（Discord 开发者门户 / QQ 机器人平台）而不是「取消」，关闭依赖标题栏 ×、Esc 与遮罩。正文内的按钮行用 `.modal-actions` + `.modal-actions-start` 复用同一分区规则（如「立即备份」左、「恢复所选备份」右）。只有一个按钮时（自动生成的「关闭」）保持贴右。
3. **开关按所在层级区分样式**——二级窗口中的开关使用勾选式选项（圆角选项底，方框勾选在左、说明文字在右），适用于翻译链路、自动备份及日志自动滚动；一级桌面端页面中的设置项开关使用胶囊轨道。转发组表格中的启用复选框和机器人状态卡片按钮不属于此规则。开关仍使用原有 `role="switch"`、`aria-checked` 与保存处理，不改变行为。一级页面的设置开关保持无外围按钮框，只保留 32×18 胶囊轨道；卡片开关按内容宽度排列，说明文字与轨道间隔 8px。
4. **编辑定时消息**沿用同一套规则：窗口正文单列，不显示「消息列表」标题或说明段、批量工具按钮；每条消息内容始终展开，正文与附件直接铺在窗口正文中，发送方式、周期和时间控件在同一行底端对齐；不设折叠按钮、附件说明段和分隔线；图片、视频或音频通过方形上传图标按钮添加，已有附件时显示方形垃圾桶按钮。接收群由消息组统一指定；「＋ 新增」打开只含一条空白消息的编辑器，保存后追加到当前组；消息行编辑只打开对应的一条消息，保存和删除按消息组与消息 ID 定位。

转发组沿用现有 Tab 与组级操作栏、固定布局表格、ID 截断/复制、危险图标按钮、拖动排序及空状态。配置向导位于设置页“应用”卡片末行；“外观与窗口”中“界面动画”排在“界面主题”上方；设置行右侧文字按钮与跳转链接共用页面字体、14px 字号和 20px 行高。两栏底部同一紧凑 footer 只放新增/注册等主操作，转发组页面不再挂平台外链；平台外链改挂到 Discord Bot / QQ Bot 配置二级窗口的底栏左侧。窄窗口继续沿用单栏断点。白名单新增/审核与转发群一致，直接在「QQ → QQ」页指定分栏底部操作栏完成，不再有独立的设置行与二级弹窗；手动转发与共享翻译卡遵循统一的小卡片标题规则，翻译卡内部不画分隔线。日志自动滚动使用 `.settings-switch-track`，提供 `role="switch"` 与实时 `aria-checked`，原保存流程不变。

五个功能页不显示全局日志。统一入口为“设置 → 启动与维护 → 运行日志”，使用标准 ModalShell：最高 320px 的深色等宽控制台内部滚动，正文下方排列级别、自动滚动和「消息追踪」，空间不足时换行；底栏两侧分别为「复制日志」和「清空日志」。日志级别说明不单独占行。连接诊断列表顶部不显示分隔线，刷新诊断位于底栏左侧，关闭按钮位于右侧。根 HTML 预留稳定滚动条空间，切页与折叠不改变可用宽度。

机器人状态卡与 X / Bilibili / YouTube RSS 状态卡在正常运行时显示渐变扫光；机器人状态卡的扫光使用与“运行中”徽标一致的主题绿色，RSS 状态卡沿用各自状态色。当前选中且启用的转发组标签也显示扫光，暂停的组不显示。设置 → 外观与窗口提供“界面动画”开关，默认开启；偏好保存在本机 localStorage，并立即作用于所有页面，开关所在行的扫光延伸到卡片左右内缘并扫过完整横向区域，边缘为直角，光带本身保持原宽度。转发组标签使用更宽、更淡的扫光，减弱中央亮斑的集中感。深色主题保持原有强度，浅色主题降低不透明度以减弱对比度；斜向光带每 8 秒从左向右循环。机器人动效要求进程运行、当前 QQ Bot 已连接；Discord 与总览还要求 Discord 已连接。连接任务仍在进行时视为等待状态，不显示失败光效；所需连接未建立且没有进行中的网关任务时，状态卡才切换为 4 秒循环的红色呼吸光。停止或连接检测中不显示该失败光效。非输入态连续输入 wrelayfail 可切换失败光效预览，再输入关闭。RSS 动效沿用现有绿色“运行中”判定；停止、等待连接和请求/解析失败时不显示。装饰层位于内容后方，不拦截点击，也不改变卡片尺寸和间距；关闭“界面动画”或系统启用“减少动态效果”时隐藏这些光效。

下拉框保留原生值和事件，控件文字与箭头垂直居中并分列两端；菜单使用圆角面板，选项文字与控件内边距对齐，悬停时提供清晰的品牌色反馈。当前值仍显示在控件上，但从展开列表中隐藏。桌面端保留的 HTML `title` 提示统一转为面板自制 `ui-tooltip` 样式，鼠标悬停或键盘聚焦时显示；不再使用浏览器/系统原生 title 浮窗，包括禁用控件和动态添加的提示。总览统计与链路状态、表格全选启用框、折叠按钮、转发组常用图标及指定设置开关属于无重复提示项，不显示 Tooltip。

`panel/web/discord-page.js` 保留原文件名，现为五个功能页共用的展示适配层：按页面配置选择工作区；移动现有控件而非复制控件，跨页切换先还原再安置。QQ 用户白名单表格（`#userList` / `#userBody`）与「＋ 新增」「注册审核」按钮直接写在 QQ → QQ 页转发组的第二个分栏中，沿用原元素 ID 与事件绑定，不再弹窗搬移。样式复用 Discord 的同一组规则，总览和设置页不采用紧凑功能页模板。表格行、复制、拖动、保存和配置弹窗仍沿用原处理函数。

Discord 转发频道表格将名称、来源和频道 ID 分列显示，顺序为「名称 → 来源 → 频道 ID」；Bilibili 转发组来源表分列显示「类型 → 名称 → 来源」，名称可在来源编辑中填写，来源显示来源值。来源行右侧统一提供「内容筛选」、编辑名称与来源地址、移除三个按钮，Discord 来源仍可点击打开对应频道。五条链路来源表的操作列统一预留 120px，以完整显示三个图标按钮；Steam 来源与 Steam 链接分列，链接可点击打开。各链路的来源与 QQ 群行内编辑按该行标识定位。移出成员按点击时的转发组和成员标识定位，列表刷新或重排后仍处理原条目。

QQ → QQ 页的授权用户行尾不再单独设置失败通知。QQ 状态栏最右侧按钮槽显示 MingCute 告警图标开关；开启后向名单中所有已启用用户发送失败与维护提醒。设置页的失败通知开关与状态栏图标共用同一全局配置。

X、Bilibili 和 YouTube 的 RSS 详情卡使用相同的状态区（桌面端由顶部图标入口打开二级窗口，普通网页端在对应页面显示）：标题独占首行，徽标与来源/轮询/投递统计同行，地址与间隔位于下一行。状态、来源、上次轮询、发现、发送、地址及间隔保留，Bilibili 另保留积压与保护设置。异常时保留统计信息，错误原因和普通统计分别着色。当前账号没有可轮询的 Bilibili 来源时，状态卡与上游状态入口用中性状态显示「无启用来源」。已有可轮询来源且首轮未完成时，上游入口才显示等待首次轮询。工作区采用与 Discord 相同的双栏、底部新增/注册结构；1280px 及以下转为单栏。Bilibili 来源注册选择来源范围和 UID、标签名或关键词地址；注册来源可在转发组行内编辑显示名称与来源地址。Discord、X、Bilibili、YouTube 和 Steam 的来源行右侧统一提供「内容筛选」、编辑名称与来源地址、移除三个按钮；X、Bilibili 和 YouTube 的备注、关键词、消息类型、推文/投稿类型及翻译选项均由「内容筛选」管理，并统一采用勾选框胶囊。Steam 的事件、DLC/捆绑包、新闻 feed 和翻译条件由同名内容筛选窗管理，基本编辑窗只编辑名称与地址。Bilibili 内容筛选沿用按关键词筛选及投稿类型选择的布局；UP 主来源支持视频、专栏、动态，标签与关键词来源仅支持视频。来源筛选不再提供额外标签、作者或标题条件。Bilibili 不再在自身页面放手动转发卡：手动转发统一收拢到「QQ → QQ」页的统一「手动转发」卡，右侧「已注册来源」弹窗与「内容筛选」二级窗口的 Bilibili Tab 在此卡中提供；Bilibili Tab 只显示该链路支持的消息类型（文字、图片、链接、视频）。说明文字采用与 X 相同的单句格式，短链接与视频发送细节放在帮助提示中。QQ 白名单统一在「QQ → QQ」页转发组的「QQ 授权用户」分栏管理。三页 Tab 较多时仅标签条横向滚动，组操作不换行。

「Bilibili」页在转发组卡片下方有一张「自动解析」卡片（`#bilibiliAutoResolveCard`，标题为「自动解析」，帮助提示标题为「Bilibili 自动解析」）：标题行右侧是帮助图标，`#hint-bilibili-auto-resolve` 只保留用户要照做的操作说明（打开后群里的 B 站视频链接会被发回本群、需要群管理员先在机器人资料页开启「接收所有消息」、拿不到视频时不回复），下载与去重等实现细节不写进气泡；卡内一句话说明在上，单个 √/× 胶囊开关 `#btnBilibiliAutoResolveToggle` 贴底靠左，点击沿用 `saveAndReload()` 保存整份配置，不新增接口。该卡片包在 `#pageBilibili > .func-cards` 网格里，因此与其他小卡片同宽同高（1500px 视口实测 584×164px），且整组仍位于 `#bilibiliFgBody` 工作区之外，不参与 `discord-page.js` 的控件移动与还原。

「YouTube」页沿用 Bilibili 的状态区与双栏转发组结构：`#youtubeCard` 显示运行徽标、来源/轮询/投递摘要、轮询间隔和限速表图标。检查进行时显示已完成频道数量和最近最多三个频道的检查结果，说明气泡写明官方频道 RSS、第一期只转发标题/封面/链接；页面状态栏右侧提供钥匙图标，打开独立的 YouTube Data API Key 二级窗口，原状态卡不再放置密钥输入；`#youtubeFgBody` 左侧为「YouTube 频道」、右侧为「QQ 接收群」，频道行统一提供内容筛选、编辑和移除操作，翻译选项位于内容筛选中；注册窗口收集频道 ID、@开头的频道用户名或主页链接及显示名，窗口底部不显示技术说明。该页没有手动转发、自动解析或下方小卡片，也不提供视频本体开关；内容筛选窗口只显示文字、图片、链接三种类型，关键词字段与 X/Bilibili 来源筛选共用布局。侧栏和总览的 YouTube 入口使用 MingCute 的 `youtube_line` 空心播放图标，与其他品牌图标同库同粗细。

QQ 定时消息在「QQ → QQ」页按消息组管理：外层工作区卡复用 Discord 转发组的深浅主题边框、圆角、内边距与标题尺寸；消息组标签沿用相同 Tab 和添加按钮样式，当前组标签行末提供暂停/恢复、重命名和删除操作。内容区左右两栏为「定时消息」和「QQ 接收群」，复用转发组面板底色、标题留白、折叠按钮、表格列、行高、复选框、拖动手柄、行内图标和底部新增按钮栏；桌面视口 1280px 及以下转为单栏。消息表格左侧勾选启用内容，表头复选框控制当前组全部消息；右侧显示发送计划、编辑与删除操作；编辑和删除只处理所点的消息。目标表沿用 QQ 接收群的名称、账号与 Group OpenID 列宽及编辑/移出操作样式。目标群启用状态保存在当前消息组内，表格勾选和全选只影响当前消息组；暂停消息组时该组内计划全部停止投递，投递同时受 QQ 群全局停用限制。

编辑器内不绘制每条消息的卡片边框、底色或内边距，消息正文和附件直接铺在二级窗口正文中，所有配置始终展开；不显示“消息列表”标题、折叠按钮、图片说明段或分隔线，以释放编辑空间。图片、视频或音频附件使用方形上传图标和垃圾桶图标按钮；未添加附件时隐藏移除按钮。接收群由消息组统一指定。计划支持间隔、日历及按时点发送一次性任务，周期、日期/时间与发送方式同一行底端对齐，窄屏上下排列；按时点发送的执行状态持久化，过期一分钟后不补发。日期统一显示为年/月/日，日期时间显示为 YYYY/MM/DD HH:mm。新增消息从主面板「＋ 新增」进入；删除通过主面板消息行的垃圾桶按钮完成。编辑器不显示顶部发送目标说明段、批量折叠/展开或添加消息工具按钮。`scheduled_message.target_groups` 仍作为消息组接收群配置保留在后端。各功能页顶部徽标只描述进程“运行中/已停止”，Bot 下拉框独立描述连接状态，RSS 徽标保留原运行/等待/错误判定。总览与各功能页的机器人状态徽标，以及 X/Bilibili/YouTube/Steam 状态徽标统一采用 36px 最小高度和 4px 9px 内边距；不修改后端状态判断。

全局 Bot 与翻译服务配置统一在设置页，直接使用 `btnDiscordConfig`、`btnQQConfig`、`btnTranslationConfig`，不再通过功能页的隐藏按钮代理；YouTube API Key 作为「机器人与服务」独立设置行进入同一配置窗口，YouTube 与 Discord 页面状态栏右侧也提供钥匙快捷入口；原功能页重复配置按钮已删除；翻译服务路由放在「QQ → QQ」页的共享「自动翻译」卡，五条链路开关收在该卡「翻译链路」二级窗口内，Discord/X/YouTube 来源级配置仍保留。

三页验证使用隔离示例数据，所有写请求被测试预览拦截：1366×768、1920×1080、2560×1440 及各自 125%/150% 等效内容视口，共 27 组布局检查无页面横向溢出或表格按钮裁切；双栏等高、窄窗口单栏。配置弹窗、定时任务空/非空入口、日志折叠和运行工具、断连及 RSS 错误展示已检查。未触发真实机器人启停、转发、补发、保存或删除；等效视口验证不代表完成系统 DPI 切换测试。

### 总览与公共外壳

总览页使用紧凑的横向机器人状态栏、两列转发链路卡片和单行最近消息（链路卡顺序为 Discord、X、YouTube、Bilibili、QQ、Steam，第六张 Steam 卡落在第三行右格）；主题切换统一从设置页进行。Windows 标题栏使用独立的原生窗口模块绘制：高度 38px、Logo 24px、三个窗口按钮各 46×38px，尺寸随 DPI 缩放；关闭按钮悬停为 Windows 风格红色，最大化时自动绘制还原图标。窗口拖动、双击、系统命令、Snap 和边缘缩放通过原生消息处理，关闭行为由持久化桌面偏好决定，默认收起托盘。

桌面端首次打开进入运行总览，集中展示机器人控制状态、各转发链路的运行状态和配置数量，并提供进入对应管理页的快捷入口。左侧保留 Discord → QQ、X → QQ、YouTube → QQ、Bilibili → QQ、Steam → QQ、授权 QQ → QQ 手动转发和设置导航。

侧栏 8 个导航入口与总览 5 张链路卡使用统一的单色图标槽：Discord、X、Bilibili、YouTube 与 QQ 使用各自品牌图标（同样取自 MingCute：`discord_line`、`social_x_line`、`bilibili_line`、`youtube_line`、`qq_line`），Steam 使用 MingCute Core Regular `steam` 品牌图标，总览与设置使用 MingCute line SVG（`home_1_line`、`settings_1_line`）。MingCute 使用 Apache 2.0 许可。
浅色主题下，总览五个链路图标使用浅色品牌底色（YouTube 为浅红底），并保留足够的图标前景对比度；深色主题沿用原配色。

设置页单独管理桌面主题、应用版本和更新检查。更新检查读取 GitHub 最新稳定发行版。更新检查以平铺行呈现：“自动检查更新”开关（默认开启，首次加载自动检查一次）、“更新状态”行（说明文案 + 行尾的“检查更新”按钮）。检查到可安装的新版本后按钮变为“立即更新”，点击后下载安装包并显示进度百分比与当前步骤，随后启动安装向导由用户确认，不会静默替换正在运行的程序。机器人账号、翻译服务、启动方式、备份和诊断作为独立的维护区域保留。桌面端首次进入运行总览，并记忆当前页面。

桌面页面使用统一的颜色、间距、圆角和控件尺寸变量。各页标题与说明共用主内容对齐线；总览隐藏非必要的标题栏快捷操作，机器人统计和启停按钮紧凑排列，窄窗口时导航收为 60px 宽的图标栏，导航起点与普通侧栏顶部对齐，图标在侧栏内居中，隐藏的文字标签不保留额外间距。转发组列表换行时，MingCute 添加图标按钮紧跟最新组标签，当前组操作栏在可换行布局中同排靠右；桌面端横向滚动的链路标签保持操作栏固定在右侧。

Steam 页面复用链路页的机器人状态栏和右侧状态详情入口，使用 MingCute `steam` 品牌图标；桌面端从状态入口打开运行状态卡。Steam 状态详情显示等待 QQ 连接、首轮检查、扫描进度和来源检查结果，以及来源启用数/总数、上次轮询、发现数、发送数和积压数。打开面板、进入对应链路页或启动、重启机器人时，Steam 和 YouTube 的状态读取独立于更新检查，并各自定期刷新；商店地区使用带中文名称的下拉列表，轮询间隔和投递保护入口集中在设置行。商店地区和轮询间隔修改后即时保存；右上角投递保护按钮打开二级参数窗口，保护参数在该窗口单独保存。来源与转发组采用与其他链路一致的标签及操作栏布局；没有已保存转发组时自动创建「转发组1」，且始终保留至少一个组。当前组的暂停、重命名和删除操作位于标签右侧，只有存在其他组时才显示删除按钮。Steam 桌面转发组卡片与 Bilibili 保持一致：上下/左右内边距为 12px/18px，标题行使用统一控高并留 12px 下间距，标签底部间距为 10px，双栏间距为 12px/16px。标签下方并排显示 Steam 来源和 QQ 接收群面板，两侧面板均可折叠并在底部提供「新增 / 注册」操作栏；内容只列出当前组成员，通过「新增」从已登记来源或接收群中选择，接收群启用状态保存在当前 Steam 转发组内，也可从底部打开注册审核。两个面板均采用与 Bilibili 相同的表格、空状态行、列宽和行尾操作样式；Steam 来源的公告、新闻、折扣、发行阶段及捆绑包选项在来源编辑窗口中配置。来源和转发组在交互后自动保存，群状态修改只影响当前组。Steam 说明文字与首次启用基线提示收在转发组标题的帮助气泡内，不在卡片中另占说明段落。窄屏时左右面板改为单列，轮询字段自动换行。商店地区下拉弹层固定从选框下方展开，列表高度限制在约 42svb 或 320px，并以连续国家/地区选项显示，不再显示大洲分组标题。

模块标题使用清晰的中性色，蓝紫色用于导航、主操作和选中状态。转发组暂停状态以中性标签表达，当前组仍使用统一的品牌选中态。桌面配置入口以设置行呈现；外部链接按钮共享相同图标、尺寸和次级层级。机器人状态区的 PID 与转发统计采用一致的字段和值层级，并将“开机自启”显示为开关。

桌面按钮悬停反馈按用途分组：普通次级操作与外部链接统一使用轻微底色、边框和文字对比变化，并平滑过渡；设置中的“问题反馈”保持相同边框反馈，“更新状态”行的检查/更新按钮使用普通次级按钮样式。设置开关只高亮外壳，保留开关轨道的开/关颜色，悬停和键盘聚焦时不弹出文字提示，仍保留无障碍名称；主操作继续使用简洁反馈，危险操作保留危险色，禁用按钮不响应悬停。图标工具、帮助和折叠按钮保留各自紧凑的专用反馈。

转发频道、来源、接收群和白名单表格共享行高、复选框和操作按钮样式。列宽按卡片可用宽度分配，不使用强制最小宽度；长值省略显示，可悬停查看完整值并右键复制。窗口变窄时转发列表改为单栏，更窄时隐藏次要的 QQ 账号列。日志保持固定高度并在内部滚动，可复制或清空，并能切换自动跟随；页面主体保留主要纵向滚动。

长 OpenID 显示头尾片段，复制使用完整值并固定显示 2 秒结果提示。表格删除操作默认使用低饱和图标，悬停或键盘聚焦时再显示危险色。总览中的 RSS 状态与来源数量分开呈现，机器人状态标题采用圆形 Help 图标，统计分隔线弱化。“运行概况”与“转发组”采用同级标题和外层卡片，链路卡片作为内嵌层级；六张链路卡使用统一的 Chevron 和三行文字基线，保持双列布局与原有尺寸，其中 Discord → QQ 卡片底色沿用 Discord 转发频道二级面板颜色。最近消息中的链接预览优先显示域名，摘要占剩余宽度并省略，时间固定右对齐；“更多”采用可键盘操作的文字入口，悬停仍可查看完整内容。导航仅当前页面具有 active 与 aria-current，普通 hover 采用弱中性色。

QQ → QQ 的定时消息设置区在空状态时说明尚未配置，并提供添加入口。

总览最终微调：标题至首卡片、状态区至运行概况、链路区至最近消息的间距各增加 6px，不增加卡片高度。机器人信息区在常用宽窗口约占整卡 60～65%，较窄窗口优先保证字段可读；Bot 下拉框上限 210px，为箭头预留 32px。链路第二行将绿色状态词与灰色说明分开，QQ 使用“已连接 · 授权手动转发”，避免重复状态。最近消息摘要及“更多”使用普通字重和较弱文字层级，字号保持不变。

- `#chanList` 与 `#groupList` 均为 100% 宽、固定布局、最小宽度 0，字号 13px；单元格纵向内边距 7px、横向 6px，垂直居中，内容超出时裁切。表头高 36px、字号 12px、常规字重；数据行 CSS 高度为 44px，32px 操作按钮和单元格内边距可能使实际行盒略高于该最小高度。
- 每行下方为 1px `var(--table-border)` 分隔线，悬停行叠加约 4% 前景色的轻微底色；不画竖向网格线。空状态占位行最终高度为 48px，提示文字居中并允许换行。
- 两张表头两列保持一致：拖动列 34px，启用列 38px；启用复选框 18×18px，水平居中。虽然 HTML 内有列宽声明，桌面端共享表格规则会以 34px/38px 强制覆盖它们。

#### 拖动与行内操作

- 每行最左侧是 34px 拖动手柄列，显示 14px「三横」图标，静止时为弱化的次级文字色，悬停后提高对比度；可拖动时指针为抓取手势。拖动源行降至 45% 不透明度，目标行上方或下方显示 2px 强调线。

- 频道行依次提供内容筛选、编辑、移出当前转发组三个操作，因此操作列 120px；QQ 群行提供编辑、移出当前转发组两个操作。常态按钮背景透明，普通图标为低强调色；悬停或键盘聚焦出现次级底色和边框。已启用的筛选按钮使用主色底，移出操作使用危险色，悬停/聚焦时再加强危险底色。

#### 底部新增操作栏与成员行为

- 面板底部 `.addrow` 固定占 58px 高度（`--control-height` 36px 加上下各 11px 内边距），操作按钮高 36px，按钮间距 8px；新增为主色按钮，旁边的注册审核/频道注册使用次级按钮。
- 表格只展示当前转发组的频道和 QQ 群成员。组内增删改的是成员关系；频道的「启用」复选框控制频道全局状态，接收群的复选框控制当前转发组内的投递状态。各转发组用独立停用群列表保存本地状态，新加入成员默认在本组启用；旧配置按原 QQ 群全局状态迁移，以维持已有投递范围。QQ 群管理中的全局停用仍可阻止所有链路投递。Discord 频道与 QQ 群的可见顺序来自各自全局数组，拖动行会改变其全局顺序；转发组标签顺序单独保存。

### 定时消息组复用转发组样式（2026-11-18）

- QQ 定时消息外卡使用与 Discord 转发组相同的 1px 边框、10px 圆角、12px 上下和 18px 左右内距，下方卡片间距 16px。标题为 18px，标题行最小高度 36px 并垂直居中；标题与组标签之间留 14px。
- 消息组使用同款 36px Tab、36×36px 虚线添加按钮及 8px Tab 间距。当前消息组标签末端操作栏提供暂停/恢复、重命名和删除按钮；暂停状态显示在组标签上，并停止该组内全部计划投递。删除操作允许删除最后一个消息组，仍调用原确认与保存处理。
- 「定时消息」与「QQ 接收群」两栏等宽、横向间距 16px、行高 12px；桌面窗口宽度不大于 1280px 时改为单栏。两类面板采用与 Discord 成员面板相同的底色、8px 圆角、左右 14px 内缩、无深色边框；浅色主题使用 `#f3f5fa` 底色和 `#dfe4ef` 边框。标题为 15px 粗体，内边距上 16px、下 13px，折叠按钮 32×32px。
- 两张表格均使用 13px 常规字重正文、12px 表头、36px 表头高、7px×6px 单元格内距、44px 数据行高、48px 空状态行高和 1px 行分隔线；QQ 群名称与账号沿用转发组的 12px 行字号。拖动列/启用列固定为 34px/38px，启用框 18×18px；行图标按钮 32×32px，图标 15×15px，操作项间距 4px。
- 定时消息表的「发送计划」列 180px、操作列 84px，消息列占剩余宽度；QQ 群表的名称、账号、Group OpenID、操作列分别为 20%、16%、34%、84px。底部「新增」操作栏与转发组相同，占 58px，按钮高 36px、间距 8px。编辑器的日历弹层以年/月标题、周一至周日标题和日期网格组成，旁侧为可滚动的 24 小时/分钟列；日期时间字段统一以 `YYYY/MM/DD HH:mm` 展示，保存仍使用本地 `YYYY-MM-DDTHH:mm` 与 `HH:mm` 值。日历计划按“周期 → 周期参数 → 发送时间”排列：每周参数用可多选的星期下拉面板，每月日期和每年月份/日期使用下拉选择；周期下拉、星期触发器、月日和年月选择器使用紧凑宽度，星期触发器复用周期控件的外观且不拉伸填满剩余空间。字段分别继续保存到 `weekdays`、`day_of_month`、`month`、`day`。附件文件名在编辑器中单行省略，图片或视频文件名悬停或键盘聚焦时显示图片或视频首帧预览；视频不自动播放，预览取决于桌面环境的解码能力。一次性计划的界面名称为「按时点发送」，内部 `once` 类型、执行状态与时区语义不变；不调用浏览器/系统原生日期或时间 picker。上述样式不改变逐条启用、接收群勾选、拖动排序、编辑、删除和保存语义。
- 两个面板的折叠行为必须成对同步：点击任一侧时同时隐藏/显示两侧内容，并同步两个按钮的折叠图标和 `aria-expanded`。实现上须将 `scheduledGroupMessageContent` 与 `scheduledGroupTargetContent` 登记为 `FORWARDING_PANE_PAIRS` 的一对；新增其它双栏面板时也必须登记其配对，不能只给单侧切换。
- 消息组「＋」按钮由 `#scheduledMessageGroupTabs` 内的委托事件处理。新增后立即切到新组并通过 `saveScheduledMessageGroups()` 持久化；保存完成后组仍须存在，不能只在当前 DOM 暂时显示。新增按钮与普通组 Tab 保持同一行及既定的 36×36px 控件尺寸。
- 定时消息附件配置使用 `attachment_id/type/mime/name/size` 描述；文件按 Bot 账号存放于 `data/scheduled_message_media/<profile>/`，只接受服务端验证过签名的 PNG/JPEG/GIF/WebP、MP4/WebM、MP3/WAV/OGG/M4A，单个附件与全部定时消息附件各自不超过 30 MiB。保存时必须检查描述字段与实际文件匹配；旧版 `image_data/image_name` 仍按原来的图片格式、单张 2 MiB 和图片合计 3 MiB 上限读取，并在成功保存配置时转为文件附件。替换或移除已保存附件时，只在配置成功保存后清理未引用文件；未保存的孤立上传文件可在 7 天后清理。桌面本地 API 桥接层需将 `x-file-name` 与媒体请求一起转发，上传接口才可取得原始文件名。普通备份默认包含附件文件，恢复时逐项校验附件路径、文件签名、类型和大小；附件文件按二进制处理并归属到对应 Bot 配置。
- 消息组接收群选择窗口打开期间，状态轮询不能用服务端快照重建定时消息草稿；确认保存时按消息组 ID 更新当前草稿，避免轮询替换组对象后把刚勾选的接收群写进已脱离草稿的旧对象。
- 定时消息「QQ 接收群」表的启用复选框控制当前消息组的接收状态；表头全选只作用于当前消息组可见的接收群。按“全部群”动态路由时仍显示当前 Bot 工作区的全部群，启用状态与 QQ 群全局停用分开保存，实际投递要求两者均可用。
- 定时消息表的消息正文、发送计划、群名称和账号单行中间省略，悬停显示完整值。消息正文右侧同一行显示附件类型（附图、附视频或附音频），正文过长时省略以保留附件标记；消息正文、群名称和账号支持右键复制完整值，消息正文复制保留原始换行。发送计划不提供右键复制，仍可通过键盘复制。Group OpenID 继续使用 ID 单元格复制规则。拖动手柄、启用框和行操作按钮不作为可复制数据。
- 转发组样式复用必须覆盖完整卡片，而不只是换标题或外框：统一比较主题色、面板底色/边框、控件字号与字重、内外间距、双栏尺寸和高度、表格列与行高、复选框、拖动手柄、编辑/删除图标、底部操作栏及其基线。优先复用 Discord 转发组的 CSS 变量和组件规则；不要在定时消息页另设字体或局部色值，避免出现颜色、字体、卡片尺寸、拖动/编辑/删除控件缺失等不一致。
## 新增选择与注册审核

各链路从已注册项新增、Discord 全部可读频道和群／用户注册审核窗口采用与已注册频道一致的圆角边框列表行。选择框位于左侧，编辑、删除或审核操作位于右侧；频道分组及审核识别码筛选保留原有行为。单链路窗口的标题栏不增加链路切换控件。

新增、注册和审核窗口没有可用项时，使用正文大小的灰色常规字重提示，并保持文案简短；原有操作按钮与逻辑不变。

## 转发消息卡片

所有转发链路的「内容筛选」在翻译下方提供「消息呈现（全局）」及「图片化转发」勾选项。筛选、翻译和消息呈现的勾选项采用统一高度，文字与方框垂直居中。开启时同排显示「浅色模式」，默认深色。两种主题统一在右上角使用点阵，页尾左侧放来源地址，右侧放短线二维码。深色用深底浅码，浅色用浅冰蓝底深蓝码。文字、Unicode 表情和 Discord 自定义表情按消息顺序排列。Steam 折扣的百分比在价格栏右侧垂直居中。四个圆角之外透明，正文和点阵底色保持不透明。可发送的视频作为卡片之后的 QQ 视频消息。
