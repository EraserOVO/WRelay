# 个人 QQ 接入（NapCat / SnowLuma）

WRelay 通过 OneBot v11 反向 WebSocket 连接协议端。不同账号可以分别使用 NapCat 或
SnowLuma 并同时在线；同一 QQ 号只允许一个连接，不自动切换协议端或发送账号。
协议端安装、QQ 登录和进程管理由用户在协议端完成。

个人 QQ 的来源和转发组按账号保存在 `data/bot_profiles/personal_<QQ号>.json`。
切换账号后可在总览页文件按钮中导出或上传 JSON 快速配置；导入需要对应目标账号的接收群并预览确认。
连接令牌、全局授权和定时计划不随账号配置复制，详见 [Bot 独立配置](BOT_PROFILES.md)。

## 接入步骤

1. 更新项目依赖，重新启动 WRelay。编译版须重新构建，仅替换网页文件不能启用后端适配器。
2. 打开「设置 → 个人 QQ」，添加名称、实际登录 QQ 号、协议端、访问令牌，启用并保存。
   令牌为 16–256 位、不含空白。编辑时留空保留原令牌，保存后的令牌不会回传页面。
3. 在协议端创建 OneBot v11 反向 WebSocket 连接，填写窗口显示的地址
   （默认 `ws://127.0.0.1:18082/onebot/v11/ws`）及相同令牌，然后连接。
   协议端须发送 `X-Self-ID` 与 `Authorization: Bearer <令牌>` 请求头，并支持
   `get_login_info`、`get_version_info`、`get_status`、`get_group_list`、`send_group_msg`、`send_private_msg`、`get_msg`，
   并启用群聊和私聊 message 事件上报（推荐数组消息格式）。
4. 重新打开个人 QQ 窗口查看状态及协议端报告的版本。实际登录 QQ 号及在线状态校验通过才允许发送。
5. 点击连接的「接收群」，明确选择注册群。切换左上角 QQ 工作区，在自动链路转发组内添加这些群。
   仅注册群不会自动建立来源路由。

新增、启停个人连接无需重启 WRelay。停用后立即阻止新发送，连接关闭与状态刷新最多约 15 秒。
改令牌后需让协议端使用新令牌重新连接；换协议端前先断开旧端。连接窗口重新打开时刷新状态。

允许仅使用个人 QQ：先保存并启用个人连接，再移除官方 QQ 配置。首次启动仍需存在 `.env.prod`；
模板官方 QQ 占位配置在已有启用个人连接时会在当前进程屏蔽。首次配置向导仍服务官方机器人，个人号使用上述设置入口。

## 范围与身份

- 支持 Discord、X RSS、Bilibili RSS、YouTube RSS 四条自动链路群投递。
  各来源筛选、翻译、限速和媒体规则继续生效；YouTube 仍只发送标题、封面和链接。
- 支持文字、图片、音频、视频；本地媒体转为字节编码发送，不把本地文件路径交给协议端。
  HTTP(S) 媒体由协议端下载，实际媒体能力及大小限制取决于协议端与 QQ。
- 第二期支持白名单私聊管理、授权手动 QQ → QQ、Bilibili 群链接解析和定时消息。
  请求/通知事件仍忽略，不自动同意好友或入群申请，不提供 QQ → Discord 或群间自动同步。
- 目标群为 `personal:<群号>`，发送账号为 `personal:<QQ号>`；官方目标仍用原 OpenID。
  同一群只绑定一个个人账号。旧的无绑定目标仍由官方机器人处理，不自动回退给个人号。
- 改由其他个人账号发送同一群时，先从已注册群列表删除旧绑定，再用新账号添加该群并重新加入转发组。
  群标识不会因账号或协议端改变，已有去重记录继续生效。

## 第二期使用方法

1. 用户先私聊个人号发送 `/注册`。刷新面板后，在「QQ → QQ」白名单选择该 `personal:<QQ号>` 用户并启用。
   登记默认禁用，不自动取得权限；该个人 QQ 身份与官方机器人的用户 OpenID 分开。
2. 获授权用户私聊 `/菜单` 查看命令。支持运行状态、群/频道/权限列表、转发组及详情、补发状态、
   `/定时消息` 查询/开启/关闭/清空和 `/重启`。管理权限与原官方白名单相同，涉及全局设置。
3. 私聊发送普通内容，再发送 `/转发 列表`、`/转发 序号` 或 `/转发 全部`。
   私聊候选为全局已启用接收群，包括已绑定的个人号及官方目标；实际发送仍按目标账号路由。
4. 群内手动转发须由已授权用户发起，来源群必须启用且绑定当前个人号。把来源群和接收群加入同一个
   已启用 QQ → QQ 转发组，发送 `/转发 列表` 后引用内容并发送 `/转发 序号`。
   普通群消息不会自动转发，群内不支持「全部」。
5. 内容记忆仅保留当前账号/会话最近十分钟内本进程已接收的普通消息，最多 1000 条，断线清理。
   引用未观察到的旧消息时会提示重新发送内容；不读取任意历史消息。未引用时使用本人最近消息。
   支持文字、表情文字标记、图片、音视频；本地路径、合并转发和暂不支持的附件明确拒绝。
   私聊的 Discord/X/Bilibili 内容链接复用原有手动解析、筛选和翻译服务，不提供 YouTube 手动转发。
6. Bilibili 群链接解析沿用「QQ → QQ」页自动解析开关，只在启用且绑定当前账号的接收群内生效。
   普通成员贴受支持视频链接即可触发（不要求管理白名单），命令、提及机器人或自身消息不解析。
   沿用 360P 下载、大小限制与失败不补链接规则，不向其他群自动同步。
7. 在定时消息中选择个人接收群，或包含个人群的 QQ 转发组，也可使用「全部群」。
   **已有「全部群」计划也会包含已启用的个人群**。个人号验证通过即可启动定时循环，无需官方 Bot 在线。

管理回复及命令结果使用纯文本，不依赖官方机器人 Markdown 按钮。手动转发与群链接回复也使用
第一期的片段去重和待确认保护；手动命令重复事件不会再次执行。允许重试仅解除阻止，手动命令和
群链接没有后台重试队列，需重新触发；定时消息每次计划使用不同触发时间，不补发错过的计划。

## 重复保护与待确认

原有来源游标和群投递去重继续生效。个人投递另按来源、消息、目标群和实际片段内容记录成功状态，
避免多片段消息重试时重复发送成功部分；身份不包含协议端或发送账号。
成功记录复用 `delivery_dedup.sqlite3` 的有效期及容量限制（90 天、最多 100000 条），并非永久保证。

每次发送前先向 `personal_qq_uncertain.json` 写入待确认记录。明确返回失败时解除占位，
按原策略重试；超时、断线、进程退出或没有返回消息编号时保留记录，该片段不自动再发，
也不因结果未知另发降级链接。记录损坏时阻止发送。

在「设置 → 个人 QQ」核对群内消息后选择：

- **确认已送达**：记录该片段成功，后续重试跳过。
- **允许重试**：解除阻止，由现有队列下次尝试发送，不会点击后立即发送。
  原请求若实际成功，允许重试可能产生重复。源任务若已到期或移除，不会重新创建任务。

个人号不接收原有官方机器人管理员失败通知。

## 文件与验证

`data/personal_qq.json` 含连接及令牌，不进入普通配置备份，迁移机器时需另行安全保存。
高级「包含运行状态」备份包含待确认文件及投递数据库；恢复会影响重复保护，应与来源队列一起使用。
普通配置备份只有目标绑定等设置，不能代替连接凭据。

`scripts/test_personal_qq.py` 与 `scripts/test_personal_qq_inbound.py` 使用隔离文件及模拟账号验证配置、媒体、混合路由、持久去重、
未知结果处理、实际 ASGI WebSocket 握手、重复连接拒绝、登记不授权、撤权复查、引用隔离、群解析开关与计划投递身份；不连接真实 QQ。
仍需部署后的 NapCat / SnowLuma 真实账号联调确认具体版本的媒体表现。
