# WRelay

WRelay 是一个基于 NoneBot2 的 Windows 消息转发服务。当前代码包含四条相互独立的消息链路：

- Discord → QQ：实时转发和离线补发
- X/Twitter RSS → QQ：通过 RSSHub 轮询 X 账号并转发
- Bilibili RSS → QQ：通过 RSSHub 按 UP 主、标签或关键词轮询新投稿并转发
- QQ → QQ：授权用户通过私聊命令手动转发文字或 Discord 消息

项目不提供 QQ → Discord 自动转发，也不做双向同步。

## 功能

### Discord → QQ

- 实时监听已启用的 Discord 频道并转发到已启用的 QQ 群
- 支持多个 Discord 频道、多个 QQ 群和独立的 Discord 转发组
- 多个 QQ Bot 时可在面板左上角切换 Bot 工作区，分别配置各自发现的 QQ 群目标
- 支持文字、图片、音频、文件、链接、Discord 自定义 Emoji 和 Embed 内容
- 支持 Discord 回复消息，转换为 QQ 可读的引用文本
- 清理 Markdown 标记，并将用户、角色、频道、`@everyone` 等提及转换为可读文本
- 支持按 Discord 用户名、关键词和消息类型筛选
- 频道与 QQ 群分别维护发送游标，避免重复转发
- QQ 群发送失败不会影响其他群，失败群会在重试或补发时继续处理
- 失败消息会持久化到 `data/retry_pending.json`，进程重启后继续重试；媒体字节不写入队列
- 支持媒体并发下载、大小限制、发送重试、429 限流退避和链接降级
- 视频媒体优先以 QQ 视频消息发送，下载或上传失败时自动降级为文字链接
- Discord 或 QQ Bot 重连后自动补发离线期间的未转发消息，可限制每个频道单次补发数量
- 可选失败通知：按冷却时间向管理员反馈投递失败，避免重复刷屏
- 每条投递会记录最终结果、目标群和重试次数，供面板消息追踪查看

### X/Twitter RSS → QQ

- 通过 RSSHub 定时轮询 X/Twitter 账号
- 来源漏斗的“消息筛选”可并列设置关键词、推文类型（原创/转发/引用）和消息类型（文字/图片/视频）；各维度同时启用时取交集，旧配置中的“文件”会迁移为“视频”
- 支持原创内容、转发、引用内容、图片和视频
- 支持 RSS ETag/304 缓存，减少重复请求
- 对 RSSHub 的 429、5xx 和连接异常做同轮退避重试（最多 3 次）；其他 4xx 快速失败
- RSSHub 暂时不可用时回退到 X 公开时间线，保持订阅轮询不中断
- RSSHub 与本程序常同时开机启动：启动后 4 分钟内连接被拒视为“等待 RSSHub 启动”，不计入失败轮次也不触发告警
- 使用独立的来源游标去重
- 同一推文命中多个来源时，按 X 原生推文 ID 和 QQ 接收群跨来源去重；最近 90 天内已确认送达的群不会重复收到
- 管理面板可配置投递保护：默认最短发送间隔 5 秒、每小时最多 300 条、每个来源积压上限 100 条；限速按所有 X 来源合计，积压队列持久保存并在后台逐条发送
- QQ 未连接、发送失败或媒体处理失败时保留游标和队列条目，连接恢复后继续补投
- 管理面板提供 RSS 运行状态、最近轮询结果、积压数量和失败原因
- 来源筛选可设置自动转发消息类型（文字/图片/视频）；与关键词及推文类型同时设置时取交集，消息类型会控制是否发送媒体

### Bilibili RSS → QQ

- 通过 RSSHub 轮询 Bilibili 新投稿
- 支持按 UP 主 UID、Bilibili 标签或关键词注册来源
- 支持多个来源和独立的 Bilibili 转发组，可分别选择 QQ 接收群
- 同一投稿命中多个来源时，按 Bilibili 投稿 ID 和 QQ 接收群跨来源去重；最近 90 天内已确认送达的群不会重复收到
- 来源名称直接显示 UP 主 UID、标签名或关键词，不提供自定义备注
- 来源注册只选择 UP 主 UID、Bilibili 标签或关键词范围并填写值；来源漏斗可设置消息筛选（关键词、投稿类型、消息类型），各维度同时设置时取交集
- 支持可调的最短发送间隔、每小时上限和每来源积压上限；积压超限可选择保留最新或保留最旧
- 限速队列持久化保存，RSS 突发投稿不会在一次轮询中集中发送；Bilibili RSS 请求按来源串行访问，并对 429/5xx/连接异常做退避重试
- Bilibili 标签/关键词 RSSHub 路由以及 UP 主动态路由可能依赖 Chromium 或有效的 `BILIBILI_COOKIE_1`；上游 412 通常会被 RSSHub 转成 503
- 保留“自动转发来自 Bilibili 中[UP 主名称]的投稿”来源头（优先使用投稿作者，RSS 缺少作者时回退到注册来源）；按来源的消息类型筛选发送标题（文字）、投稿地址（链接）、封面（图片）和视频本体（视频）。自动投递不发送作者行、标签、其他分类、简介及播放统计
- 消息类型筛选勾选“视频”时即尝试上传视频本体，超过媒体大小上限（默认 30 MiB）、多段视频或下载失败时发送视频链接；不勾选“视频”则连视频链接也不发送
- 私聊手动转发统一在「QQ → QQ」页的紧凑「手动转发」卡管理：「已注册来源」按钮打开弹窗，用 Discord / X / Bilibili 三个 Tab 分别查看已注册频道/账号/来源；右下角「消息筛选」对三链路各自独立设置消息类型筛选。视频本体按“视频”类别控制（旧配置里的“文件”会自动迁移为“视频”）
- 手动转发引用的内容（未引用时取最近一条消息）可以是投稿视频、专栏或动态链接（专栏与动态共用 `bilibili.com/opus/{id}`，也支持 `/dynamic/{id}` 与 b23.tv 短链接）。专栏发送标题、简介摘要、封面和专栏地址；动态发送正文文字、封面和动态地址；视频行为不变
- 首次启用来源或 QQ 群时建立游标基线；UP 主专栏/动态 feed 首次启用时也分别建立基线，不批量刷出 RSS 历史
- RSSHub 暂时不可用、QQ 未连接或发送失败时不推进游标，恢复后继续补投
- 与 X 链路相同：启动后 4 分钟内 RSSHub 连接被拒视为“等待 RSSHub 启动”，不计入失败轮次

### Bilibili 自动解析

- 默认关闭，在「Bilibili」页转发组卡片下方的「自动解析」卡片开启；只对已登记且启用、且属于当前 Bot 的 QQ 群生效，不新增群选择器
- 群成员发送 Bilibili 投稿视频链接（`bilibili.com/video/BV…`、`av…`，支持 `?p=` 分 P）或 `b23.tv` / `bili2233.cn` 短链时，机器人取消息中第一个 Bilibili 链接，跟随短链重定向后下载视频本体，并以被动回复把视频文件发回同一个群
- 下载失败、超过媒体大小上限（默认 30 MiB）或视频不是单段时静默跳过，不再回复提示或原链接；直播、番剧、专栏、动态和其他站点链接同样静默，不发错误消息
- 同一群内同一视频（按投稿编号与分 P）10 分钟内只发送一次，并有在途去重避免并发重复下载
- 机器人自己发送的消息、以 `/` 开头的命令、@ 机器人的消息和私聊消息都不触发，避免与群 @ 提示重复回复
- 前提是群管理员在机器人资料页开启「接收所有消息」，否则普通群消息不会推送给机器人，本功能收不到任何链接
- QQ 小程序分享卡片依赖适配器保留的 `ark_data`，当前版本不支持

### 自动翻译

- 「QQ → QQ」页提供一张共享「自动翻译」卡片：首选与后备服务由全项目共用；卡片左下角的「翻译链路」按钮打开二级窗口，窗口内四个整行开关（链路名在左、轨道在右，外围无描边或常态底色）分别批量启用或关闭 Discord → QQ、X/Twitter RSS → QQ、Bilibili RSS → QQ 与 QQ 手动转发的翻译，点击后立即保存
- Discord 频道和 X 账号仍可在各自来源表格中用翻译图标单独设置是否翻译、是否保留原文和是否显示时间；Bilibili 来源由「翻译链路」窗口的链路开关统一控制
- 支持腾讯 TMT、OpenAI 兼容 AI API 与本机 Ollama（loopback:11434，适用于 Qwen 等本地模型）；所有翻译服务失败时仍发送原文
- AI API 仅在模型不存在/不支持、并发受限或明确容量/节点不可用时查询备用模型；普通网络超时与配额类 429 不触发模型轮换
- 面板「翻译服务配置」显示最近一次真实翻译成功使用的工作模型；AI 检测记录只表示独立检测结果，两者可能不同
- 检测记录只展示检测类型和原因，不包含 API 地址或密钥

### QQ 手动转发

授权 QQ 用户可以使用：

```text
/定时消息                       查询定时消息状态
/定时消息 <开启/关闭/清空>       管理定时消息
/转发 列表                      查看可转发目标群与转发方法
/私聊转发                       私聊查看同一份名单（与 /转发 列表 相同）
/转发 1 3                       把引用消息转发到第 1、3 个群
/转发 全部                      私聊转发到全部已启用群（群聊无此项）
/注册                           点击菜单按钮即可提交用户注册申请
/菜单                           查看菜单
```

使用 QQ 自带的“回复”引用一条消息，再发送 `/转发 序号`（可一次写多个、可重复序号），机器人直接把被引用的内容转发到目标群并回复一次结果。没有引用时使用该用户最近一条普通消息（600 秒内），因此也可以先发内容再发命令；普通文字消息仍会收到「未知命令」提示，这是正常现象，不影响缓存；直接发送 Discord / X / Bilibili 链接时只缓存为待转发内容，不再回复「未知命令」。目标名单为纯文本编号，不提供按钮；群聊目标限定为与当前群同属至少一个 QQ 转发组的其他已登记群，私聊目标是全部已启用群。

引用的内容可以是文字和图片/附件。若内容本身是 Discord 消息链接、X/Twitter 状态链接或 Bilibili 链接（投稿视频、专栏、动态，含 b23.tv 短链接），WRelay 会抓取对应内容并复用媒体发送逻辑；Bilibili 视频手动转发会尝试发送封面和视频本体，超出媒体大小上限、视频分段或下载失败时发送链接；专栏和动态发送标题或正文、封面与对应页面地址。机器人消息和命令消息不会被转发。「QQ → QQ」页的紧凑「手动转发」卡左下角「已注册来源」按钮用 Discord / X / Bilibili 三个 Tab 分别查看各链路已注册频道/账号/来源，右下角「消息筛选」分别配置各链路手动转发的消息类型筛选（X 支持文字、图片、视频，Bilibili 支持文字、图片、链接、视频，窗口内只显示该链路可用的筛选项）。三类链路共用同一套已授权 QQ 用户白名单。

群聊 QQ→QQ 手动转发会以“转发于「群名」：”标注来源群，后接空行和正文。含图片时先发送来源与正文的文字消息，再单独发送图片，避免 QQ 客户端将图片显示在正文前；纯文字转发仍在同一条消息中。

### QQ 权限与注册审核

- 自动记录发现的 QQ 用户 OpenID 和群 OpenID
- 私聊点击菜单中的“提交用户注册”按钮，或发送 `/注册`，即可提交用户注册申请
- 在群内 @机器人发送 `/注册群`，即可提交当前群注册申请；群聊不再展示独立菜单，`/菜单`、仅 @机器人及未知命令统一显示当前群可转发目标列表
- 每条注册申请会收到固定的 8 位申请识别码（格式 `XXXX-XXXX`）；请把识别码转给管理员，用于在审核列表中对应申请。识别码只用于核对，不代表授权。
- 已登记的群不能重复申请；待审核群再次提交时会返回原识别码。用户注册同样去重：已在 `qq_user_openids` 登记的用户再次发送 `/注册` 会提示“已经登记、无需重复申请”，待审核用户再次提交会返回原识别码。管理员可在注册审核列表粘贴识别码，筛选并定位对应申请。
- 注册申请按当前 QQ 用户/群 OpenID 绑定，不要求提供 QQ 号、昵称、群号或群名称；可选地附加完整资料以便审核时查看
- 私聊发送未知斜杠命令或普通文字时，会提示“该命令未知，点击下方按钮展开菜单：”并附菜单按钮（已授权用户的普通文字同时会缓存为最近转发内容；直接发送 Discord / X / Bilibili 链接时只缓存，不回复该提示）；群聊中的 `/菜单`、仅 @机器人、@机器人后发送未知内容及未知斜杠命令，都会显示当前群可转发目标列表；@其他成员不会触发提示
- 管理员可在面板审核用户和群注册申请
- 审核通过只会加入配置，默认仍为禁用状态，必须由管理员手动启用
- 保存用户昵称、群名、账号和最后活动时间，供管理面板展示
- 身份资料与权限列表分开保存，身份识别不会自动授权

### QQ 私聊管理命令

私聊 `/菜单` 为手机常用操作提供运行状态、手动转发、定时消息、注册申请和重启五个入口。「手动转发」打开纯文本目标群名单与转发方法（同 `/转发 列表`，见上文）。注册申请入口可查看用户/群待审核申请，也可提交用户注册申请。自动转发组、Bot 账号、QQ群、权限用户和离线补发等低频查看/维护命令不再列入主菜单；相关桌面管理能力保持不变。私聊发送未知斜杠命令时，除「展开菜单」外还会附一个以该命令原文为动作的按钮（enter 模式），误点只会重发同一条未知命令。群聊不显示独立菜单：发送 `/菜单`、仅 @机器人、@机器人后发送未知内容或发送未知斜杠命令，都会显示当前群可转发目标列表；群注册仍通过 `/注册群` 提交。

授权用户可以使用：

```text
/运行状态                       查看机器人状态和统计
/群列表                         查看 QQ 群列表
/频道列表                       查看 Discord 频道列表
/权限列表                       查看私聊权限列表
/补发状态                       查看离线补发状态
/补发状态 开启/关闭             开关离线补发
/补发状态 执行/清空/刷新        触发、清除或刷新补发状态
/定时消息                       查看定时消息状态
/定时消息 开启/关闭/清空        管理定时消息
/重启                           重启机器人
/菜单                           查看菜单
```

这些管理命令需要桌面管理进程运行；窗口收起到托盘时仍可使用，退出桌面端后暂不可用。转发机器人本身可继续运行。

私聊 `/菜单` 会返回标题为“WRelay菜单”的按钮面板，菜单本身不包含再次打开菜单的按钮；按钮标签使用纯文字，不添加 emoji 或装饰符号。私聊菜单提供运行状态、手动转发、定时消息、注册申请和重启入口；「手动转发」打开纯文本目标群名单与转发方法。私聊发送未知命令时会提示“该命令未知，点击下方按钮展开菜单：”并附菜单按钮，另附一个以该未知命令原文为动作的按钮。群聊没有独立菜单；群聊发送 `/菜单`、仅 @机器人、@机器人后发未知内容或未知斜杠命令，都会显示当前群可转发目标列表。按钮点击后自动发送对应中文斜杠命令并直接收到结果，不需要再点发送键；`/定时消息` 的查询结果下方附带开/关/清空按钮；转发名单不再提供按钮，转发时由用户引用消息后直接发送 `/转发 序号`。命令结果及按钮触发的后续回复使用 Markdown 一级标题，替代原来的方括号标题；按钮发送失败时仍优先保留标题样式。按钮使用 QQ 客户端 8983+ 的自动发送特性，旧版本会退化为把命令填入输入框（仍可用）；命令解析与权限校验与手输命令一致。按钮类型由 `QQ_BUTTON_MODE` 控制：默认 `enter`（指令按钮自动发送，聊天里会多出一条命令消息）；`callback`（回调按钮，点击后机器人直接回复、用户不产生消息）实测在 WebSocket 接入下点击会提示「请求第三方失败」，只在开放平台接入方式为 Webhook 时可用。

### Windows 桌面管理程序

界面沿用深色风格，导航图标与“打开”按钮使用统一尺寸。网页配置、诊断、备份等二级窗口共用分级宽度、固定标题/操作栏和内部滚动区，正文统一按网格起排、底栏按钮左右分区、开关使用胶囊样式；具体规范见 [界面设计说明](docs/DESIGN.md)。Windows 原生系统对话框保留系统样式。

桌面窗口通过 WebView2 加载本地页面，管理操作在桌面进程内执行，不再监听 `18090`。机器人自身的本机 `18082` 接口继续提供运行状态与补发等能力；QQ 私聊管理命令通过 Windows 本机管道与桌面进程通信。桌面端提供：

- 启动、停止、重启机器人
- 机器人异常退出后的自动拉起
- Windows 开机自启
- 管理 Discord 频道、X/Bilibili 来源、QQ 接收群和私聊权限（QQ 接收群与授权用户并排显示在「QQ → QQ」页转发组中）

- 注册新的可读 Discord 频道、X 来源和 Bilibili 来源

- 查看 X RSS 和 Bilibili RSS 轮询状态

- 在机器人状态卡片中开关失败通知
- 编辑 QQ Bot 与 Discord Bot 配置
- 多个 QQ Bot 时通过左上角 QQ Bot 下拉框切换当前工作区；Discord → QQ 与 X → QQ 页面只显示该 Bot 的目标群，
  不需要在每个群行单独选择 Bot
- 桌面窗口使用 38px 自定义 Windows 标题栏，保留系统缩放、双击最大化/还原和 Snap；窗口按钮统一尺寸，关闭悬停显示红色；窗口位置、尺寸及最大化状态会保存在 `data/desktop_window.json`，并在显示器变化后回到可见区域。应用图标、托盘与 Windows 快捷方式统一使用 WRelay 主标识；侧栏 6 个导航图标与总览 4 张链路卡统一采用 MingCute 单色 line SVG 图标

桌面端四个转发页按“运行状态（含 RSS 状态）→ 转发组 → 其他卡片”排列；状态卡、RSS 卡与下方卡片间距统一为 16px，下方卡片按从左到右、从上到下排布并遵循统一尺寸规则：Discord 的「离线补发」也作为其中一格，小卡片同宽同高，动作按钮一律贴卡片左下角（成对的图标动作才靠右下角），胶囊开关默认也在左下角，左侧已有按钮时改贴右下角（右下角另有按钮则紧贴其左侧），卡片中央不放成段解释文字，详细说明只写在标题旁的问号提示里，批量或次要设置改由卡底按钮打开二级窗口。卡片二级窗口沿用同一套规则：正文按网格单列起排、每行左右缘与正文内边距对齐（需要并排的用等宽两列），主要动作按钮（保存 / 确定 / 恢复 / 清空）贴底栏右下角、取消与其它入口贴左下角，窗口内与卡片上的开/关按钮一律用「启用补发」同款胶囊开关（文字在左、轨道在右）。总览浅色模式使用较浅的链路图标底色。布局参考见 [docs/DESIGN.md](docs/DESIGN.md)。

## 快速开始（Windows）

当前安装脚本和桌面程序仅支持 Windows。正式安装包提供带 WRelay 名称和图标的可执行程序，目标电脑无需预装 Python；源码运行需要 Python 3.10 及以上。安装包会在缺少 WebView2 Runtime 时安装该组件。

1. 正式安装包使用编译后的 `WRelay.exe` 桌面程序和 `WRelay.Bot.exe` 机器人程序，安装时从 `.env.example` 生成 `.env.prod`；源码目录运行 `install.bat` 时，如果没有内置 Python，则创建 `.venv` 并安装项目依赖。

   安全依赖已锁定为 `cryptography==50.0.1`、`multidict==6.9.1`，QQ 适配器使用仅修改依赖元数据的本地兼容补丁。
   源码安装需完整保留 `vendor/` 并使用 `pip install -r requirements-lock.txt -e .`；Windows 需使用 64 位 Python。
   现有安装包用户需安装重新构建的版本，单独更新仓库不会替换已安装的运行时。详见 [补丁来源与验证](vendor/README.md)。
2. 源码版本如果不存在 `.env.prod`，安装脚本会从 `.env.example` 生成配置模板。
3. 双击 `启动面板.bat`，打开 WRelay 桌面窗口；安装包用户可用桌面或开始菜单快捷方式。
4. 全新未配置时会显示首次配置向导；已有用户可从「设置 → 应用 → 配置向导」进入。先选择 Discord、X、Bilibili 或 QQ 授权私聊转发，再按步骤填写所需账号、检查连接、审核并授权用户、选择接收群和来源，最后确认启用。
5. 账号基础配置可直接在界面完成。QQ 账号为共同必需项；只有使用 Discord 时才需要 Discord Token。需要本地 HTTP 代理时，可在 `.env.prod` 配置 `DISCORD_PROXY`；账号仍由向导保存，再由用户点击「启动／重启并检查」使其生效。
6. Discord 需要本机网络可访问；`DISCORD_PROXY` 用于 Discord API、Gateway、Discord 托管媒体以及 X/Twitter 媒体 CDN（`pbs.twimg.com`、`video.twimg.com`）下载，也可改用系统虚拟网卡（TUN）路由。程序会清理通用代理环境变量，不通过 `HTTP_PROXY` 指定本地端口；同时会移除系统代理绕过列表中的方括号 IPv6 条目（如 `[::1]`），避免 httpx 把 `:1]` 当成非法端口而中断 QQ/Discord 连接。X/Bilibili 需要可访问的 RSSHub 服务，向导可检测来源，但不会安装 RSSHub。

向导沿用桌面端深浅主题和公共二级窗口样式，支持上一步、稍后配置和从设置恢复进度。进度保存在 `data/onboarding.json`，不包含密钥；账号仍由原凭据文件保存。已注册来源和群会复用，重复确认不会重复创建同一转发组。审核不会自动授权，用户授权和群启用均需明确操作。

结果页区分配置保存、连接状态和投递记录；向导不自动向群发送测试消息，按页面说明主动验证。QQ 分支引导现有授权私聊流程，授权范围仍是全局白名单与已启用接收群，不创建群聊互转规则。

详细的 Bot 创建、权限、`group_openid`、频道登记、代理和 RSSHub 配置方式见 [docs/SETUP.md](docs/SETUP.md)。

## 配置与权限说明

- Discord 频道、X/Bilibili 来源、QQ 群和 QQ 用户是否启用，以 `data/settings.json` 为准。
- Discord、X 和 Bilibili 分别使用独立的转发组配置；全局启用和转发组成员关系必须同时满足，消息才会发送。
- QQ 官方机器人使用 `group_openid`，不能从普通群号直接推算；同一个实体群被多个 Bot 发现时，
  每个 Bot 会保存自己的 OpenID 和转发目标关系。
- 旧配置中没有 Bot 归属的群继续由第一个已连接 QQ Bot 处理；面板状态卡片会显示当前工作区的连接状态。
- 自动发现 OpenID 只负责记录，不会自动授权。
- `.env.prod` 包含机器人密钥，请勿提交或外传。
- 公域 QQ 机器人可能受到主动消息权限、时段和频率限制。

- `data/bilibili_protection.json`：Bilibili 限速时间窗、待发送积压和延后跳过记录
- `data/stats.json`：成功、失败和当日转发统计
- `data/message_trace.json`：最近投递结果追踪（自动限制保留数量）
- `data/qq_identities.json`：QQ 用户和群身份资料
- `data/qq_registrations.json`：待审核注册申请
- `data/channels_audit.json`：Discord 频道权限审计结果
- `data/logs/bot.log`：机器人运行日志

这些文件属于运行时数据，不应提交到版本库。

## 长期运行与自动维护

从 0.1.1 起，桌面管理程序默认每小时创建一份经过校验的备份，保留最近 30 份，保存到
`data/auto_backups/`。在「设置 → 启动与维护 → 自动备份与维护」可查看告警、关闭自动备份、
立即备份或恢复所选有效备份。恢复会先校验、保存恢复前副本，暂时停止机器人；成功后按操作前状态启动。
备份包含面板配置、游标、重试队列、X/Bilibili 队列与来源状态及投递去重数据库，不含账号密钥。
恢复旧运行状态可能产生重复投递或漏发，因此需要在界面确认；不会静默回滚配置或自动清空损坏队列。

同一 RSS 来源连续三轮失败、队列/游标文件损坏和自动备份失败会显示维护告警；启用失败通知且在 QQ
用户白名单勾选「告警」后，也会向这些已授权用户提醒。QQ 不可用时无法通过 QQ 通知，恢复连接后再尝试。
独立的 `WRelay.Guardian.exe` 看护桌面管理进程：异常退出或管理接口连续 2 分钟无响应时，等待 30 秒后
恢复到托盘并保留机器人运行意图。正常退出/重启会结束旧看护；10 分钟内最多自动恢复 5 次，避免无限重启。
电脑关机、休眠、退出 Windows 登录或整个进程树被结束时不能继续工作。

请开启随 Windows 启动，保留桌面端在托盘，保持电脑通电联网；本机自动备份不能替代异地备份。
